# 报告 PDF 流水线

B 轨解决的是「要好看、要能直接发出去」的报告。和 Word 轨的分工：

| | Word 轨 | PDF 轨 |
|---|---|---|
| 谁改 | 客户、政府部门会拿回去编辑 | 只读，发出去就是终稿 |
| 字体 | 宋体保底，任何机器都能开 | 思源，本机渲染成 PDF 后字体已固化 |
| 版式 | 受 Word 样式系统限制 | CSS 完全控制 |
| 场景 | 要签字盖章、要归档 | 对外展示、提案、宣传性报告 |

## 三个文件的分工

```
报告.md  ──md2html.py──▶  报告.html（单文件，CSS 内联 + logo base64）
                          └──html2pdf.js──▶ 报告.pdf
                                              └──lint_pdf.py 体检
```

**HTML 本身就是交付物**，不只是中间产物。可以直接发链接、丢浏览器、微信里打开看。PDF 是顺手导出的。

单文件的意思：没有任何外链。CSS 内联、logo 转 base64。断了网也能打开，转发不会出现「图片裂了」。

## Chromium 打印的三个硬限制

### 一、页眉不能用 position: fixed

看着最直觉的做法是 `.page-head { position: fixed; top: 12mm }`，让浏览器每页重复绘制。**实际会压在正文第一行上。**

原因是打印时 `fixed` 相对的是「页面内容框」而不是纸张——`top: 12mm` 是从内容区顶端往下 12mm，而正文正是从内容区顶端开始排的。页眉就落进了正文区域。

改成负值（`top: -19mm`）能把 X 轴修对（logo 落在 28mm、编号右端在 184mm），**但 Y 轴不受控**——页眉被甩到页面底部 253mm 处。这条路走不通。

正解：用 Playwright 的 `headerTemplate`，它专门画在页边距区域里，位置由 `margin.top` 决定。

### 二、headerTemplate 不吃页边距，得自己缩进

`headerTemplate` 的容器是从**纸张左边缘**起算的，不是从版心起算。所以第一版 logo 直接顶在 0mm，与正文的 28mm 对不上。

退回版心用 `margin: 0 26mm 0 28mm`，**不能用 padding** —— `border-bottom` 画在 padding box 外沿，细线会跟着拉满整张纸。

量出来对齐的效果：

| 元素 | 左边 | 右边 |
|---|---|---|
| logo | 28.0mm | 68.0mm |
| 页眉细线 | 28.0mm | 184.1mm |
| 正文 | 28.0mm | 184.0mm |
| 报告编号 | 149.2mm | 184.0mm（右距纸边 26mm）|

这张表是拿 pymupdf 读 `page.get_image_info()` / `get_drawings()` / `get_text('blocks')` 量出来的，不是目测。

### 三、header 里的布局只认表格固定列宽

想当然的三种写法，在这个渲染上下文里全部失效：

| 写法 | 结果 |
|---|---|
| `display:flex` + `justify-content:space-between` | 编号紧贴 logo 后面 |
| `width:100%` / `width:calc(100% - 40mm)` | 被忽略，容器收缩到内容宽度 |
| `position:absolute; right:0` | 包含块不对，编号跑到 logo 下方 |

根因是容器宽度收缩到内容宽度，`text-align:right` 没有多余空间可对齐。

唯一管用的是 `<table>` + **固定列宽**：

```html
<td style="width:40mm">logo</td>
<td style="width:116mm; text-align:right">编号</td>
```

40 + 116 = 156mm，正好版心宽。列宽不给具体值时，td 依旧收缩，问题照旧。

### 四、封面不能带页眉，但 headerTemplate 是全局的

没有 `@page :first { header: none }` 这种语法。所以：

1. 第一趟：隐藏正文，只留封面，`headerTemplate` 传空 div → 出封面 PDF（无页眉无页码）
2. 第二趟：隐藏封面，留正文，正常带页眉 → 出正文 PDF（页码从 1 起）
3. 用 pypdf 合并

页码因此天然是「封面不编号、正文从 1 开始」，符合惯例。

**注意**：渲染封面那一趟必须解除 `.cover` 的 `break-after: page`，否则封面后面会跟一张只有页眉页码的空白页。

## 版面高度必须算准

A4 297mm − 上边距 25mm − 下边距 25mm = **247mm 内容区**。

封面高度写 200mm + padding-top 60mm = 260mm，超了 13mm，直接多出一张空白页。这种错误肉眼在屏幕上完全看不出来——HTML 里只是"一页有点长"。

现在封面用 `height: 205mm` + 子块绝对定位（`cover-top` / `cover-mid` / `cover-bottom`），高度可控，也不会因为 flex 在分页时被拆开。

## 分页：靠标题，不靠横线

```markdown
## 二、公司概况      ← 这一行本身就是分页指令（每章另起一页）

---                 ← 这条是水平分隔线，不换页

:::pagebreak        ← 真要强制分页（比如附录前插一页附件清单），写这个
```

早先 `---` 兼作分页符，真实报告立刻出问题：一份 13 章的材料有 16 条 `---`，其中 15 条紧跟 `## 一、` 这种章标题——作者写它是「隔开两章」，程序读成「这里换页」，一章被切成两三段，41 页里 21 页只有小半内容。

现在 `---` 只是水平线，章的分页由 `##` 决定。紧贴在章标题前面的那条 `---` 会被直接忽略：章都另起了，上一页末尾再留条灰线是噪音。

## 分页规则（承重段，不许改）

```css
.chapter { break-before: page; }              /* 每章新起一页 */
h1,h2,h3,h4 { break-after: avoid; }           /* 标题不孤立在页底 */
figure, .table-block { break-inside: avoid; } /* 图与表不跨页 */
table thead { display: table-header-group; }  /* 长表跨页时表头重复 */
p { orphans: 2; widows: 2; }                  /* 段落不留单行 */
```

这几条对应的是四种真实缺陷：章标题落在页底、图注与图分家、第二页开始的表没有表头、段末只剩一个字独占一行。

## 代码块 / ASCII 架构图

报告里常有 ` ``` ` 围栏画的框图（业务模式、股权结构、实施路线）。要让它排得能看，**三层缺一不可**：

| 层 | 取值 | 缺了会怎样 |
|---|---|---|
| 字体 | 西文 `Courier New` + 中文 `宋体` | 非等宽时 `│` 宽度不一致，竖线错位 |
| 行距 | `line-height: 1`（Word 里 exact = 字号 × 1.05） | 行距一大，`│` 在行间断开，整图散成虚线 |
| 换行 | `white-space: pre`，超宽只缩字号不折行 | 折一次框图就彻底看不懂 |

中文用宋体而不是思源/等线，是因为**宋体汉字正好两个半角宽**，与 `┌─┐` 的宽度假设一致。

即使用对了这三层，中英混排的原文宽度本来就不严格（全角括号与半角括号混用），右边缘仍会对不齐。所以 `lint_docx` 会提醒：**正式对外报告建议把框图改成图片或表格**——它在换字体、换纸张、转 PDF 时都可能错位，而且无法被检索。

## PDF 体检查什么

`lint_pdf.py` 做四件事，都是人眼抽查最容易漏的：

1. **页码连续性**。提取每页的「— N —」，正文序列必须从 1 连续递增。
2. **逐页内容填充率**。量的是「正文区里内容排到了百分之几」，不是「涂了多少墨」。
   - 早先按墨水占比判，一份 26,000 字 / 41 张表的报告被报出 22 页「偏空」——三线表几乎全白，墨水量 3%，但内容占满整页，全是误报。
   - 现在分三档：末页偏空正常；章末页偏空（下一页以章标题开头）只提示；中间页填充率 < 12% 才算错误。
3. **页眉对齐**。logo 左缘 vs 正文左缘、编号右缘 vs 细线右端，差 > 0.5mm 报错。
4. **无图页**。只提示不拦截。

这两项替代了「抽看几页」。排版缺陷不是均匀分布的——它集中在内容最密的页和收尾的页，抽看必漏。

## 改版式改哪里

`assets/report.css` 分两段：

- **承重段**（页面、分页、表格防粘连）：不要动。动了就复现上面那四种缺陷。
- **调味段**（`:root` 里的颜色字号）：只换变量值，不动选择器。

字号以 pt 为单位，跟 Word 轨对齐（正文 10.5pt、表 9pt、图注 8pt），两轨出的稿子视觉密度一致。
