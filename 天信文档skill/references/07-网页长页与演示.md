# 网页长页与演示 deck

同一条稿子的两种「屏幕上」出口。它们和 A4 报告的根本差别是**介质**：A4 是给打印的，这两条是给屏幕的。所以字号、行宽、留白的取值全部不同。

| | A4 报告 | 网页长页 | 演示 deck |
|---|---|---|---|
| 阅读方式 | 逐页翻 | 滚动 | 站着讲 |
| 正文字号 | 10.5pt | 17px | 21px（标题 42px） |
| 行宽 | 156mm | 720px（约 40 汉字） | 一屏 |
| 分页 | 强制分页 | 无 | 一页一结论 |
| 目录 | 手写页码 | 左侧常驻 + 滚动高亮 | ESC 索引 |

---

## 一、网页长页

### 为什么正文栏只给 720px

屏宽 1280px 时，如果正文铺满，一行接近 60 个汉字，眼睛回行会找不到下一行的起点。720px 折合约 40 个汉字，是中文长文阅读比较舒服的区间。

剩下空间给左侧目录（200px）。排版用 grid：`200px minmax(0, 720px)` + 72px 间距，整体居中。

### 目录高亮怎么做的

`IntersectionObserver` + `rootMargin: '-88px 0px -72% 0px'`。

这组数字的含义：把判定区从视口顶部往下推 88px（让开吸顶条），底部往上收 72%（只保留上部 28% 作为「当前章节」的判定区）。效果是章节标题滚到吸顶条下方不远处时才高亮，而不是一露头就高亮。

### 章节金条

品牌规范 §6.5 规定每个章节标题上方一条 3px × 48px 金色横条，那是「印章感」签名。长页里用 `h2::before` 实现，每章一个。

第一版把金条放在文档开头一次，位置是错的——它是**章节标记**，不是文档装饰。

### 打印降级

`@media print` 里把吸顶条、目录、进度条、回到顶部全隐藏，正文退回 A4 单栏（`@page` 25/25/28/26）。这样对方用浏览器 Ctrl+P 也能得到一份能看的纸质稿。

## 二、演示 deck

### 为什么砍掉 WebGL 和入场动效

参考的实现（guizang 那套）有 WebGL 流体背景和 Motion One 的逐元素入场。放在发布会很漂亮，放在客户会议室的老笔记本上会掉帧。**掉帧的演示比没有演示更糟**——讲到关键页卡住，全场等它。

所以这一版只有页面位移（`transform: translateX`，380ms），加 `prefers-reduced-motion` 时直接关掉。

### 页型判断

`parse_page()` 按内容自动判断，不需要作者标注：

| 条件 | 页型 |
|---|---|
| 有 `#` 无 `##` | 封面 |
| 含 `:::kpi` 块 | 数据页 |
| 有标题、无正文 | 章节幕 |
| 只有一段引用 | 金句页（引用放大到 30px，压得住标题） |
| 其余 | 要点页 |

### 内容垂直居中，而且必须整页居中

第一版只让 `.slide-body` 居中（`flex:1` + `justify-content:center`），结果标题钉在页顶、正文浮在中间，两者之间空出一大块。

正解是让 `.slide` 自己居中，标题和正文作为一个整体。用 `justify-content: safe center`——`safe` 关键字保证内容超长时退回顶部对齐，不会把开头裁掉。没有 `safe` 的话，内容一多就会上下同时溢出。

### 索引

ESC 打开的缩略导航。背景必须**不透明**：第一版用了 `rgba(10,10,10,.94)`，后面那页的文字透上来，跟索引项叠在一起，看着像坏了。

## 三、两条轨道的共同点

- **单文件**：CSS 内联、logo base64。断网能开，转发不裂图。
- **同一套 Markdown 约定**：与 Word/A4 四条轨道共用 `parse_blocks`，只是渲染器不同。
- **三级标记**：`--marks` 打开后【事实】【行业】【推演】带底色，用于复核场景。
- **0 圆角、白底、navy 结构色、金色单屏 ≤2 处**：与品牌规范一致，没有为网页另定一套视觉。
