# 天信实务知识库

天信所内审计 / 会计 / 税务实务的可调用能力卡集合。遇到实务疑点，按下方选卡，读「核心理念 → 判断直觉 → 天信场景 → 演练输出」走一遍即可。

## 能力卡（共 12 张）

| # | 能力卡 | 触发场景 | 文件 |
|---|---|---|---|
| 1 | 收入准则 CAS14 判断卡 | 收入确认时点/时段法、总额净额、可变对价、识别提前确认 | `cards/cas14-income.md` |
| 2 | 小企业会计准则判断卡 | 客户该用小企业还是企业准则、五不简化 | `cards/small-business-standards.md` |
| 3 | 审计准则核心卡 | 风险导向骨架、重要性、函证/监盘/截止/分析四程序、报告意见判定 | `cards/audit-core.md` |
| 4 | 监管处罚前车之鉴卡 | 审计失败五大共性、风控红线清单 | `cards/penalties.md` |
| 5 | 监管提示卡 | 中注协/财政部年度质控重点、独立性/舞弊领域 | `cards/reg-tips.md` |
| 6 | 税务实务卡 | 小微所得税、增值税小规模、个税扣缴、扣除限额、优惠、发票凭证红线 | `cards/tax-practice.md` |
| 7 | 报表编制 CAS30 卡 | 四表/三表编平、四勾稽、不平排查 | `cards/financial-statements-cas30.md` |
| 8 | 政府补助 CAS16 卡 | 与资产/收益相关、总额/净额法、递延 | `cards/government-grant-cas16.md` |
| 9 | 职工薪酬 CAS9 卡 | 工资社保个税三件套、累计预扣、辞退福利 | `cards/employee-comp-cas9.md` |
| 10 | 资产减值 CAS8 卡 | 不得转回/可转回、可收回金额、资产组 | `cards/asset-impairment-cas8.md` |
| 11 | 差错更正 CAS28 卡 | 政策/估计/差错判别、追溯调整/重述 | `cards/error-correction-cas28.md` |
| 12 | 年报审计 SOP 整合卡 | 六步流水线 + 交付清单，总控台 | `cards/audit-sop.md` |

## 使用方式

1. 按上表选对应卡。
2. 读卡内六节：一、核心理念 → 二、判断直觉 → 三、准则依据 → 四、天信场景 → 五、演练输出 → 六、关联卡。
3. 「演练输出」节给出该卡的可评测交付物与完成标准，照着产出即可。
4. 卡 1–5 构成"准则 → 程序 → 风控"审计线；卡 6–11 补齐县城所基本盘（税务/编报/中小准则）；卡 12（SOP）是总控台，把 1–11 串成六步流水线。各卡「六、关联卡」已交叉互链。

## 红线

- 本知识库为天信**内部编译**的实务参考，**仅供所内使用，不对外发布、不转售**。
- 涉及**监管处罚**等敏感内容，对外引用须经合伙人（爸爸）复核。
- 税费优惠等政策具时效性，使用前以主管税务机关 / 财政部税务总局最新发布为准（多数现行优惠执行至 2027-12-31）。
- 如需落到具体准则原文或处罚决定书细节，可联动「陈版主实务问答」Skill（`chenyiwei-bbs`）查证。
- 本卡集合不替代注册会计师的职业判断，重大疑难仍须按执业准则与所内复核流程处理。

## 反馈与改进

这份技能是 [cyhzzz/tianxin-agents](https://github.com/cyhzzz/tianxin-agents) 的**副本**。
**你在这里的修改不会自动回到仓库**——会话一结束就没了。

遇到下面任一情况，请留下改进提案，不要只在会话里绕过：

- 内容有误、政策已变、数字对不上
- 缺了某一类常见情形，你只能临场发挥
- 用户纠正了你，而纠正的内容本该写在这份文件里

### 优先：能改就直接改文件，再回传

AI 遇到技能有问题，默认做法是临场绕过——这次能用，下次还是错的。
**更好的做法是直接改 `~/.workbuddy/skills/tianxin-shiwu-kb/` 下的文件**，然后告诉用户：

> 我改了「tianxin-shiwu-kb」里的 `references/xx-yyy`，改动还没回仓库。
> 克隆 https://github.com/cyhzzz/tianxin-agents 后跑这一条就能提 PR：
> `python contribute.py --from-installed ~/.workbuddy/skills/tianxin-shiwu-kb`

这条路径最有用——它产生的是**可以逐行 review 的真实改动**，不是一段描述。

### 改不了时才交提案

政策拿不准、超出权限、只是觉得表述不清——写成文件再告诉用户：

    # 改进提案：tianxin-shiwu-kb · 内容有误

    | 字段 | 内容 |
    |---|---|
    | 技能 | tianxin-shiwu-kb |
    | 类型 | 内容有误 |
    | 位置 | references/xx-yyy.md 第 12 行 |

    **现在怎么写的**：（原文照抄，别转述）
    **应该是**：（改成什么）
    **依据**：（政策文号 / 准则条款）

存到 `~/.workbuddy/skills/_待提交改进/tianxin-shiwu-kb-<主题>.md`，然后告诉用户跑
`python contribute.py --proposal <该文件>`。没有 git 也能反馈——
去仓库开 issue 把上面这段贴进去就行。

**政策类改动必须给文号。** 没有文号的税率、优惠比例一律不收：
一份过期税率表会让客户少缴、补税加滞纳金，这种错仓库里出过六处。
**提案里不要写客户名、税号、金额**——那是公开仓库。
