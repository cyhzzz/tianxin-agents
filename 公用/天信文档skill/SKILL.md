# 天信文档与报告

这不是一个排版工具。事务所的文档有**签字的、有归档的、有被监管复查的**，所以第一件事永远是判性质，不是选字体。

## 第一步：判文书性质

判错的代价不是难看，是**不合规**。三类文书：

| 性质 | 例子 | 版式自由度 | 判断依据 |
|---|---|---|---|
| **法定业务文书** | 审计报告、验资报告、专项审计报告、资产评估报告、司法鉴定意见 | **接近零**。必备要素与段落顺序由执业准则规定 | 有没有注册会计师 / 资产评估师签字盖章，有没有报告文号 |
| **咨询与尽调报告** | 财务尽调、战略咨询、AI 赋能方案、可行性研究 | 高，可设计 | 署名是项目组，不对社会出具鉴证意见 |
| **汇报演示** | 管理层汇报、政府汇报、方案宣讲 | 高 | 有讲的人、有听的人，没有装订归档要求 |

**法定文书这条轨道，AI 能做的是把内容填准，不是把版式做漂亮。** 一旦用咨询报告的思路去美化审计报告，出的不是视觉问题，是执业风险。

拿不准时问一句：这份东西要不要签字盖章对外出具？要 → 法定文书轨；不要 → 其余两轨。

详细要素清单见 `references/01-文书分轨.md`。

## 五条轨道

| 轨道 | 产出 | 用哪套东西 |
|---|---|---|
| **A · Word 交付** | `.docx`，要打印、要盖章、要归档 | `assets/tianxin-report.docx`（咨询报告）/ `assets/tianxin-gongwen.docx`（公文）+ `scripts/md2docx.py` |
| **B · A4 报告** | 单文件 HTML + PDF，排版讲究、可直接发链接 | `assets/report.css` + `scripts/md2html.py` + `scripts/html2pdf.js` |
| **B2 · 网页长页** | 单文件 HTML，滚动阅读，手机电脑都能看 | `assets/web.css` + `scripts/md2web.py` |
| **C · 网页演示** | 单文件 HTML，横翻页，投影用 | `assets/deck.css` + `scripts/md2deck.py` |
| **D · Excel 表** | `.xlsx`，底稿 / 勾稽 / 抽样 / 测算，要复核、要算 | `scripts/build_xlsx.py` + `references/11-Excel表样与公式.md` |

前四条共用同一套 Markdown 解析器（`parse_blocks`），同一份稿子能出四种产物，不会各写一版；D 轨走表样 + 公式，不经过 Markdown。

**怎么选**：要签字盖章 → A；要发 PDF 给人看 → B；要发个链接让对方在手机上读 → B2；要站着讲 → C；**列多、要核数、要给客户填 → D**。

> 判据一句话：**文字进 Word，数字进 Excel，报告附 Excel。** 正文只放结论与关键表，完整表作附件。


### B 轨命令（A4 报告）

```bash
# Markdown → 单文件 HTML（CSS 内联、logo base64，可直接分发）

```

### 图怎么出

不要截图贴图。在 Markdown 里写 `:::chart` 块，脚本生成内联 SVG，三条 HTML 轨道自动渲染：

````markdown
:::chart bar
caption: 图 1　木制工艺品占收入 64.7%
unit: 万元
source: 企业提供的销售明细账，天信整理
| 木制工艺品 | 3120 |
| 竹藤制品 | 980 |
:::
````

四种图型 `bar` / `column` / `line` / `grouped`，参数与用法见 `references/08-图表规范.md`。
Word 轨暂不支持自动图表（需要先转 PNG），要图的话走 HTML 轨出 PDF。

字体：HTML 轨用思源（本机已装 `Noto Sans SC` / `Noto Serif SC`），比 Word 更接近品牌规范；Word 轨仍用宋体保底。这是介质差异，不是两套标准。

## 六条铁律

**一、名称先核实。** 企业全称、报告文号、签字人，写在文书上的每个专有名词都要能对回工商登记或内部台账。简称匹配错企业这种事发生过一次，两版交付物全废。

**二、事实与推演分开写，并在排版上可辨。** `【事实】`公开可核查 · `【行业】`行业通行口径 · `【推演】`未经确认。默认只留文字标记；复核版加底色（`--marks`），让复核人一眼扫出哪句还没落实。

**三、口径差异不取平均、不挑好看的写。** 两个来源数字打架，并列写出来，注明各自出处。含糊化（"大几千万"）只允许出现在演示物料上，正式报告必须给准确数与口径。

**四、每个关键数字要有分母和参照系。** 没有基数的百分比是修辞；没有参照系的水平值读者无法判断好坏。毛利率 21.4% 本身没有意义，"同业 23%–26%，本公司连续两年低于下限"才有。查不到外部基准就写"未检索到可比数据"，不要拿不相干的凑。

**五、AI 产出默认带"待复核"。** 脚本不自动去掉这个标记。谁复核、复核到什么程度，由项目负责人决定，不由工具决定。

**六、归档优先于好看。** 不用整页背景图（复印发灰、扫描 OCR 差、双面透背）；页码连续；附件单列；表格跨页重复表头。

## Markdown 写法约定

转换脚本只认这几条，别用花式语法：

| 写法 | 输出 |
|---|---|
| `# 标题` | 文档主标题（24pt 黑体，整篇一个） |
| `## 一、xxx` | 章标题（18pt） |
| `### （一）xxx` | 节标题（14pt） |
| `#### 1. xxx` | 小节（11.5pt） |
| 空行分段 | 正文段落，首行缩进 2 字符 |
| `**表 1** 说明` | 表题（深蓝加粗 9pt），放在表格上方 |
| `\| a \| b \|` + 分隔行 | 三线表 |
| `数据来源：xxx` | 来源行（8pt 灰），放在表格下方 |
| `![图 1 说明](路径)` | 居中插图 + 图注 |
| `> 文字` | 引用块（左侧 1.5pt 灰线），用于免责说明与口径提示 |
| `---` | 水平分隔线，**不换页** |
| `:::pagebreak` | 强制分页 |
| ` ``` ` 围栏 | 代码块 / ASCII 架构图（等宽、灰底、保原样） |
| 单元格里写 `<br>` | 格内换行 |

**分页靠标题，不靠横线**：`## 一、xxx` 本身就是分页指令。正式报告自动每章另起一页
（≥6 章且 ≥8000 字），短报告自动连排——拿体量判断，不拿参数判断。
真实报告里 `---` 几乎总是「隔开两章」，早先把它当分页符，一份 13 章的材料被切成 41 页、21 页只有小半内容。
详情见 `references/09-真实项目复盘.md` 第一节。

## 交付前自检

机械能查的（跑 `scripts/lint_docx.py`）：

- OOXML schema 顺序（错了 Word 会提示文件损坏，人眼看不出来）
- 占位符残留：`{{}}` / `TODO` / `×××` / `【待填】`
- 页眉有没有 logo、页脚有没有页码域
- 有没有用到禁用色（紫色系）
- 连续空段落
- 表格有没有题注（紧跟小节标题的豁免）
- 代码块字体是否等宽（不是等宽，ASCII 框图必错位）；含框图时提醒改图或表

眼睛才能查的（逐页看，不能抽检）：

- 标题落在页底、正文翻到下一页
- 表格跨页时表头没重复
- 长表某列被挤成一字宽
- 图注与图分离（图在这页、注在下页）
- 章末只剩一两句话独占整页

## 字体为什么用宋体而不是品牌规范里的思源

`references/00-品牌规范.md` 写正文用 Noto Sans SC，那是给屏幕定的。Word 文档要发给客户、交到政府部门、打印装订归档，字体必须保底——目标机器没有思源会静默回退，排版就散了。所以：

- **印刷文档**：宋体正文 + 黑体标题 + Times New Roman 数字
- **屏幕物料**：思源宋体 / 思源黑体

两者不冲突，因为介质不同。品牌感靠颜色、留白、细线维持，不靠字体。

> `python contribute.py --from-installed ~/.workbuddy/skills/天信文档与报告`

这条路径最有用——它产生的是**可以逐行 review 的真实改动**，不是一段描述。

### 改不了时才交提案

政策拿不准、超出权限、只是觉得表述不清——写成文件再告诉用户：

    # 改进提案：天信文档与报告 · 内容有误

    | 字段 | 内容 |
    |---|---|
    | 技能 | 天信文档与报告 |
    | 类型 | 内容有误 |
    | 位置 | references/xx-yyy.md 第 12 行 |

    **现在怎么写的**：（原文照抄，别转述）
    **应该是**：（改成什么）
    **依据**：（政策文号 / 准则条款）

存到 `~/.workbuddy/skills/_待提交改进/天信文档与报告-<主题>.md`，然后告诉用户跑
`python contribute.py --proposal <该文件>`。没有 git 也能反馈——
去仓库开 issue 把上面这段贴进去就行。

**政策类改动必须给文号。** 没有文号的税率、优惠比例一律不收：
一份过期税率表会让客户少缴、补税加滞纳金，这种错仓库里出过六处。
**提案里不要写客户名、税号、金额**——那是公开仓库。
