# 公文排版规格（GB/T 9704-2012）

> 这份文件解决一件事：**什么算「公文版式」，参数是多少，哪里会错。**
> 判据、命令、坑都在这里；`SKILL.md` 只管路由。
>
> 适用边界先说清：本技能做的是**正文版式**（页面、字体、字号、行距、层次序数、
> 页码、落款）。**不做的**：红头（发文机关标志）、份号密级、版记分隔线、印章、
> OFD 电子签章——那些是红头模板与电子公文系统的范围，硬做会做成「像公文但不是」。

---

## 一、三档 Word 的判据

不是「好不好看」的问题，是**这份东西要不要签字盖章对外出具**。

| 档 | 什么时候用 | 典型场景 | 页眉 | 表格 | 判据一句话 |
|---|---|---|---|---|---|
| **plain 过程稿** | 还在写、还要改、只给自己和同事看 | 草稿、会议材料、资料清单、复核底稿 | 无 | 全线表 | 出错也不外传，排版别添乱 |
| **report 咨询报告** | 对外交付，但不承担鉴证责任 | 财务尽调、可行性研究、管理咨询、AI 赋能方案 | logo + 报告编号 | 三线表 | 署名是项目组，不签注师名 |
| **gongwen 正式公文** | 对外正式行文、报主管部门、要归档 | 审计报告外壳、专项报告、请示、函、报政府的材料 | 无（版头属首页） | 全线表 | 有签字盖章、有报告文号 |

**判错的代价**：把 process 稿当交付物发出去 → 客户看到的是没页眉没编号的初稿；
把公文做成咨询报告 → 要素缺失，复核挑出来要重出。

拿不准时问一句：**这份要不要签字盖章、进不进档案？** 要 → gongwen。

## 二、页面参数（§6.1）

| 项目 | 9704 严格坐标 | 33476.2 软件坐标 | 本技能取值 |
|---|---|---|---|
| 纸张 | A4 210×297mm | A4 | A4 |
| 上白边 | 37±1mm | 34.58mm（天头 37 − 字高补偿） | **37mm** |
| 下白边 | 35±1mm | 32.58mm | **35mm** |
| 左白边（订口） | 28±1mm | 28mm | **28mm** |
| 右白边 | 26±1mm | 26mm | **26mm** |
| 版心 | 156×225mm | 156×225mm | 由上面推出 |
| 行 × 字 | 22 行 × 28 字 | 22 行 × 28 字 | — |

**为什么取 9704 严格坐标而不是 33476.2 软件坐标**：软件坐标那套（34.58/32.58）是
电子公文排版软件为了「看起来和纸质一致」做的字高补偿，只有用该软件导出时才成立。
我们用 Word / Chromium 出稿，按严格坐标给值，量出来才是 37/35。

**22 行 × 28 字是验算值，不是设置值。** 它由「三号字 16pt + 固定行距 28 磅 + 版心
156×225」推出来：28 字 × 16pt ≈ 156mm，22 行 × 28 磅 ≈ 217mm。行距若改成 1.5 倍，
行数立刻变 18 行——所以行距那条是承重的，不能当样式偏好调。

## 三、字体字号（§7）

| 要素 | 字体 | 字号 | 其他 |
|---|---|---|---|
| 份号 | 阿拉伯数字 | 3 号 | 版心左上角第一行（本技能不做） |
| 密级 / 紧急程度 | 黑体 | 3 号 | 版心左上角（本技能不做） |
| 发文机关标志 | 方正小标宋（红色） | — | 红头，属版头（本技能不做） |
| 发文字号 | 仿宋 | 3 号 | 六角括号〔〕；年份全称；顺序号不编虚位、不加「第」 |
| 标题 | 方正小标宋简体 | **2 号 22pt** | 居中；回行成梯形 / 菱形 / 长方形 |
| 主送机关 | 仿宋 | 3 号 | 顶格，后标全角冒号 |
| 正文 | **仿宋** | **3 号 16pt** | 首行缩进 2 字；**固定行距 28 磅** |
| 一级「一、」 | **黑体** | 3 号 | 首行缩进 2 字，末尾不加标点 |
| 二级「（一）」 | **楷体** | 3 号 | 首行缩进 2 字，括号端不带标点 |
| 三级「1.」/ 四级「（1）」 | 仿宋 | 3 号 | 首行缩进 2 字 |
| 附件说明 | 仿宋 | 3 号 | 左空 2 字；「附件」后全角冒号 |
| 落款机关 | 仿宋 | 3 号 | 右空 2 字（盖章）或 4 字 |
| 成文日期 | 仿宋 | 3 号 | `YYYY年M月D日`，**月日不补零**，右空 4 字 |
| 抄送 | 仿宋 | 4 号 | 顶格；末尾加句号（本技能不做版记） |
| 印发机关 / 日期 | 仿宋 | 4 号 | 印发日期后加「印发」（本技能不做版记） |
| 页码 | **宋体** | **4 号 14pt** | 一字线「— N —」；单页右、双页左 |

### 字体从哪来：三层结构

公文字体是个三层问题，混在一起就说不清：

| 层 | 内容 | 谁决定 |
|---|---|---|
| **规范层** | 标题小标宋、正文仿宋、二级标题楷体 | GB/T 9704 |
| **字库层** | 规范名常写「仿宋_GB2312」，Win7+ 系统只有「仿宋」 | 操作系统 |
| **分发层** | 方正小标宋是商业字体；GB2312 是中易字库 | 版权 |

**先纠正一个我犯过的错**：Windows 字体装在**两个**地方，只查 `C:/Windows/Fonts` 会漏——
用户自己装的字体在 `~/AppData/Local/Microsoft/Windows/Fonts`。实测本机（2026-11-01）：

| 规范要求 | 系统目录 | 用户字体目录 | 本机结论 |
|---|---|---|---|
| 方正小标宋简体 | — | `方正小标宋简体.ttf` ✓ | **有**（族名 `方正小标宋简体` / `FZXiaoBiaoSong-B05S`） |
| 仿宋_GB2312 | `simfang.ttf`（仿宋） | `仿宋_GB2312.ttf` ✓ | **有**（族名 `仿宋_GB2312` / `FangSong_GB2312`） |
| 楷体_GB2312 | `simkai.ttf`（楷体） | — | **没有**，降级到「楷体」 |
| 黑体 | `simhei.ttf` ✓ | — | 有 |
| 华文中宋 | `STZHONGS.TTF` ✓ | — | 有 |
| 宋体 | `simsun.ttc` ✓ | — | 有 |

### 处置：优先规范名，逐级降级

字体文件**不进仓库**：方正小标宋 `fsType=783`（明确禁止嵌入文档，连打包带走都不允许），
GB2312 字库版权归中易，两者都不能随公开仓库分发；中文字体单个 5–15MB，仓库总共 6MB。

所以做成「探测 + 降级」，代码在 `scripts/check_fonts.py`：

| 轨道 | 机制 | 说明 |
|---|---|---|
| **Word** | 探测本机族名，命中写规范名，否则退兼容名 | Word 的 `w:rFonts` **只能给一个名字**，没有 CSS 那种降级链 |
| **PDF** | 字体栈：规范名 → 兼容名 → 宋体 | CSS 天然支持逐级降级，最理想 |

写进 docx 的字体名按探测结果定：

```
正文   仿宋_GB2312（规范名）→ 仿宋（兼容名）
二级   楷体_GB2312（规范名）→ 楷体（兼容名）
标题   方正小标宋简体 → 华文中宋 → 宋体
```

强制切换：`build_template.py --gb2312`（规范名）/ `--compat`（兼容名）/ `--title-font 宋体`。

**使用者自己放字体**：`assets/fonts/` 是空目录（`.gitignore` 已排除），把自己合法取得的
字体放进去，脚本自动注册成 `TX-Gongwen-*`，Word 与 PDF 都跟着用，不改一行代码。
详见该目录的 `README.md`。

**一个必须知道的限制**：收件人没装字体时，Word 仍会回退成宋体——这是字体分发问题，
排版解决不了。**要保证对方看到的就是你看到的，交 PDF，不交 Word**（PDF 里字形已固化）。

## 四、层次序数与「标题不是标题」

公文里 `一、` `（一）` `1.` `（1）` **不是独立标题，是正文段落**。这个认知差一错，
整篇版式就错：

| | 咨询报告的理解 | 公文的理解 |
|---|---|---|
| 一级「一、」 | 章标题，段前段后留白、另起页 | 正文段，段前段后 0，首行缩进 2 字 |
| 二级「（一）」 | 节标题，字号小一档 | 正文段，只是换成楷体 |
| 行距 | 标题可以 1.35 倍 | 与其他正文同一固定 28 磅 |
| 编号 | Word 自动编号 | **纯文本**（复制到别处不会乱） |

本技能的落地方式：
- Word 轨：`Heading 1/2/3` 样式一律 `firstLineChars=200`、固定 28 磅、段前后 0。
- PDF 轨：`h2/h3/h4` 一律 `text-indent: 2em`、`line-height: 28pt`、`margin: 0`。
- 编号一律纯文本，不挂 `numPr`。**理由**：公文经常被复制进别的系统、被扫描、
  被二次编辑，Word 自动编号一旦脱离原文档就散架；而且国标没要求自动编号。

## 五、页码（§7.3.5）

宋体四号，一字线夹阿拉伯数字：`— 1 —`。**单页在右、双页在左。**

- **Word 轨做到了**：`w:evenAndOddHeaders` + 独立的 `even_page_footer`，奇偶页各自
  右/左对齐，页码用 PAGE 域（增删页自动重编，不是手写数字）。
- **PDF 轨做不到**：Chromium 打印没有奇偶页概念，`footerTemplate` 是全局的。
  只能统一居中。要严格单右双左只能走 Word 轨。

这条限制写在 `assets/gongwen.css` 头部，免得以后又当成 bug 来修。

## 六、落款与成文日期（§8.3）

```
:::sign
天台天信会计师事务所有限公司
二〇二六年十一月一日
:::
```

渲染成右对齐、右空 2 字（`w:rightChars=200`）。

三个容易错的：
1. **月日不补零**：`2026年11月1日`，不是 `2026年11月01日`。
2. **日期不替你格式化**：脚本原样输出。改字的风险大于省事的收益——日期是法律要素。
3. **落款不等于盖章**：本技能只排位置，不探测印章有没有盖上（那要看纸质件）。

## 八、交付前必查（本技能能机械查的）

跑 `python scripts/lint_docx.py 报告.docx`。公文版式（正文仿宋三号）会自动启用
`check_gongwen`，查五项「错了但 Word 不报错」的：

| 查什么 | 判据 | 错了会怎样 |
|---|---|---|
| 页边距 | 37/35/28/26 ±1mm | 版心不是 156×225，每行字数不对 |
| 正文行距 | 固定 28 磅 | 22 行变 18 行，整篇页数错 |
| 标题字号 | 22pt | 标题层级失真 |
| 层次序数缩进 | `firstLineChars=200` | 标题顶格，最典型的「不像公文」 |
| 奇偶页页脚 | `evenAndOddHeaders` | 页码全在右边或全在左边 |

**机械查不出的，只能逐页看**：标题是否回行成梯形、落款与印章位置是否打架、
表格跨页表头有没有重复、附件说明与实际附件对不对得上。

## 九、依据与来源

- **GB/T 9704-2012**《党政机关公文格式》——页面、字号、层次序数、页码、版记的依据。
- **GB/T 33476.2-2016**《党政机关电子公文格式规范 第 2 部分：公文格式》——软件坐标那套的来源。
- 本机三个公文类技能的实际做法（2026-11-01 对照后取舍）：

| 技能 | 判断 | 采纳了什么 |
|---|---|---|
| `gongwen-format` v2.1 | 唯一真按国标实现的，有 13 种段落角色识别、10 项检查器 | 国标参数表、检查项清单、页码与落款的取值口径 |
| `gongwen-docx` v1.0 | 生成式，但**页边距统一 2.5cm**，不符 9704 的 37/35/28/26 | 三个实现坑（两端对齐用 JUSTIFY、`cell.text=""` 留空 run、`rFonts` 四属性）、字体缺失的处理原则 |
| `gongwen-docx-format` | 只有一段代码，华文中宋 + 28.5 磅行距 + 72/80pt 边距 + 表格灰底，四处不合国标 | 不采 |

**为什么不把 `gongwen-format` 收进 `上游/`**：它是「拿别人给的 docx 刷格式」的后置
引擎，本技能是「从 Markdown 生成」的前置流水线，两条路不冲突但也不能叠——叠了就成
两套引擎、两个答案，正是仓库规矩里警告的「两份税率表」。它真正有价值的是国标参数
与检查清单，这两样已经落进 `build_template.py` 与 `lint_docx.py`，成为可执行代码，
比收一份原文更有用。
