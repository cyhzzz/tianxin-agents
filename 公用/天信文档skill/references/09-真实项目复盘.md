# 真实项目复盘：一份 26,000 字的标的尽调

> 用虚构样例测技能，测的是「会不会崩」；用真实材料测，测的是「哪里会出丑」。
> 这份文件记录第一次拿真实报告（某茶业企业标的尽调，26,000 字 / 14 章 / 41 张表 / 4 张 ASCII 架构图）
> 走完四轨时暴露的八个问题，以及每个问题的根因与修法。
>
> 教训一句话：**虚构样例永远比真实材料干净**。样例里没有 `<br>`、没有 ASCII 架构图、
> 没有 16 条 `---`、没有超长标题、没有跨页长表——真实报告全有。

---

## 一、`---` 不是分页符，是分隔线

**症状**：一份 13 章的报告输出 41 页，其中 21 页只有小半内容。

**根因**：解析层把单独一行的 `---` 当成「强制分页」。真实报告里 16 条 `---` 有 15 条紧跟 `## 一、` 这种章标题，作者写它是为了「隔开两章」，不是「这里换页」。结果每章被 `---` 又切一刀，一章拆成 2–3 段，段段不足一页。

**修法**：

| 写法 | 语义 |
|---|---|
| `---` | 水平分隔线（`<hr>`），**不换页** |
| `:::pagebreak` | 强制分页 |
| `<!-- pagebreak -->` | 同上（兼容旧稿） |

章的分页由 `##` 决定，不由横线决定：报告轨道 `--chapter-break` 让每个 h2 段落带 `page-break-before`，HTML 轨按 h2 切 `<section class="chapter">`。

**顺带**：紧跟在章标题前面的 `---` 直接丢掉。章本来就另起页，在上一页末尾留一条灰线是噪音。

**代价**：这是不兼容变更。旧稿里用 `---` 分页的地方，现在会变成一条灰线。要在迁移时改成 `:::pagebreak`——但真实项目里几乎没有这种稿子，因为 `---` 一直是「分隔两章」的意思。

## 二、引用块的多行会糊成一团

**症状**：报告抬头那一块「机密 / 委托方 / 尽调执行机构 / 尽调对象 / 编制日期 / 尽调范围 / 交易背景 / 免责声明」在 PDF 里连成一整段，读不成话。

**根因**：Word 轨把 `\n` 转成 `<w:br/>`（软换行），是好的；HTML 轨的三个 `esc()` 都只做 `html.escape`，`\n` 在 HTML 里退化成普通空白。

**修法**：`esc()` 里先把字面 `<br>` 规范成 `\n`，escape 之后再统一换回 `<br>`。三处（md2html / md2web / md2deck）必须一致，否则同一份稿在长页和 PDF 里长得不一样。

---

## 三、表格里的 `<br>` 印成了字面文字

**症状**：SWOT 矩阵里赫然出现 `策"政策风口<br>• 天台山5A景区流量可转化`。

**根因**：SWOT、并列清单这类单元格，作者几乎一定要写 `<br>` 换行。`add_inline()` 没处理，`<` 被转义成 `&lt;`，然后原样印在纸上。

**修法**：`add_inline()` 开头 `re.sub(r'<br\s*/?>', '\n', text)`，Word 的 `run.text` 会自动把 `\n` 变 `<w:br/>`。HTML 轨走第二节的 `esc()`。

---

## 四、ASCII 架构图散成一堆虚线

**症状**：原文用 `┌──┐ │ ├──` 画的业务模式图、授权架构图、路线图（4 处 62 行），在 PDF 里变成框线碎片，完全看不懂。

**根因**：解析层根本没有代码块概念。` ``` ` 围栏被当普通段落，内容是正文的宋体 + 1.75 行距——制表符在非等宽字体下宽度不一致，行距一大竖线还断。

**修法**（三层，缺一层都不成）：

1. **字体**：西文 `Courier New`、中文 `宋体`。用宋体而不是等线，是因为**宋体汉字正好两个半角宽**，与 `┌─┐` 的宽度假设一致。
2. **行距**：必须 `line-height: 1`（Word 里 `lineRule="exact"` 且值 = 字号 × 1.05）。行距一大，`│` 就在行与行之间断开，整张图散掉。这一条是最容易漏的。
3. **不折行**：`white-space: pre`。超宽时缩字号，绝不让它折行——折一次的框图就彻底废了。

**但工具只能把图排整齐，排不出「好」**：原文的中英混排宽度本来就不严格（全角括号、半角括号混用），框线右边缘仍然对不齐。所以 `lint_docx` 加了一条警告：**文档含 ASCII 框图时提醒作者改成图片或表格**——框图在换字体、换纸张、转 PDF 时都可能错位，而且无法被检索。

## 五、样式里的 `firstLineChars` 会偷偷盖掉段落级的缩进

**症状**：引用块、代码块、图片段落明明设了 `first_line_indent = Pt(0)`，实际还是缩进两个字符。列表的悬挂缩进也时灵时不灵。

**根因**：`Normal` 样式里带着 `w:firstLineChars="200"`。OOXML 规定 **`firstLineChars` 与 `firstLine` 同时存在时前者优先**，而段落级只设了 `firstLine=0`，`firstLineChars` 仍从样式继承 → 2 字符首行缩进照旧生效。改段落属性怎么改都不对，因为压住它的不是段落。

**修法**：所有要取消缩进的地方，同时把 `firstLineChars` 写成 `0`：

```python
def no_first_line_indent(para):
    para.paragraph_format.first_line_indent = Pt(0)
    ind = para._p.get_or_add_pPr().find(qn('w:ind'))
    if ind is not None:
        ind.set(qn('w:firstLineChars'), '0')
```

悬挂缩进同理，包成 `hanging_indent(para, left, hang)`。

**这一类 bug 的特征**：改的地方明明对，就是不生效，而且 Word 不报错、不提示。排查时第一件事是**把段落和样式的 `w:ind` 都打印出来比对**，不要相信"我设过了"。

## 六、长表格跨页后没有表头

**症状**：风险清单表从第 25 页断到第 26 页，续页上只有一行数据和页码，读者不知道这行属于哪几列。

**根因**：没有设 `w:tblHeader`。

**修法**：`repeat_table_header(table)` 给首行加 `w:tblHeader`，位置必须按 schema 插在 `trHeight` 之后、`tblCellSpacing` 之前——插错位置 Word 会认为文件损坏。

`lint_docx` 现在会统计「表头重复了几张 / 共几张表」。

**注意**：作者在自己电脑上看不出来——他滚动时表头也没了，但他知道每列是什么，读者不知道。这类错误只有机械检查能发现。

---

## 七、封面日期取成了「今天」

**症状**：6 月 24 日编制的报告，10 月排版，封面印着「2026 年 10 月」。

**根因**：`date_str = datetime.now()`。

**修法**：从正文里抓「编制日期 / 报告日期 / 出具日期」后面的年月；抓不到才退回今天。另给 `--date` 参数显式指定。

**这条属于「工具自作聪明」的典型**：封面日期本来就该是报告的日期，不是排版的日期。工具拿不到就该问，不该替作者决定。

---

## 八、主标题把最后一个字挤成单独一行

**症状**：`某某茶业有限责任公司 标的尽调报告`（19 个汉字）断成 `…标的尽调报 / 告`。

**根因**：24pt 黑体，19 个汉字 = 456pt，超过版心 442pt。

**修法**：`_fit_title()` 按字数收字号（中文 1 字宽、西文 0.55），下限 17pt。19 字 → 22.5pt，一行放下。HTML 轨的封面标题（27pt）与正文标题（24pt）同样处理。

**顺带修了预览器的谎报**：`preview_docx.py` 原先硬编码 24pt 画标题，明明文档里已经是 22.5pt 却仍显示两行。预览器要读 run 级字号，否则它报的问题是真的、给出的方案是错的。

---

## 九、体检判据：墨水占比对表格密集的报告完全失效

**症状**：`lint_pdf` 报 22 页「偏空」，其中 5 页是真正的章末页，其余全是误报。

**根因**：判据是「非白像素占比 < 6%」。一张三线表几乎全白——细线 + 少量文字，墨水量 3%，但内容占满整页。

**修法**：改量**内容填充率**——正文区里内容实际排到了高度的百分之几（排除页眉页脚）。并且区分三种情况：

| 情况 | 判定 |
|---|---|
| 末页偏空 | 正常，内容自然收尾 |
| 章末页偏空（下一页以章标题开头） | 提示，不是错误——每章另起页的必然结果 |
| 中间页填充率 < 12% | 错误，分页切碎了 |

改完，同一份 PDF 从「22 页偏空 ❌」变成「5 页章末提示 ✅」，而且填充率普遍 90%+——说明版面利用本来就是好的。

**教训**：判据要量「意图」，不是量「像素」。墨水占比问的是「涂了多少」，而真正想知道的是「这页该不该只有这么点东西」。
