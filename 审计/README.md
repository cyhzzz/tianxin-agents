## ⚠️ 这份技能的底稿格式是通用的，不是所里的

必须说清楚：**它不是从所里已结项项目的真实底稿提炼的**，而是按通用审计实务 + 天信的品牌与行文习惯编的。

具体说：

- 索引编号规则（`ZT-{年份}-…`）是**设计出来的**，不是所里在用的编号体系。用之前先对照所里实际底稿，不一致就改 `00-底稿索引体系.md`。
- 抽样量数字（应收抽 60–80 笔、监盘覆盖金额 80%+、抽凭 20–50 笔）是通用实务经验值，文件里也标了"下限参考、非强制标准"。**最终样本量属职业判断，由项目注师定。**
- 四程序的控制要求（函证独立寄发、回函直寄、未回函必做替代、银行存款全部账户函证）是准则层面的硬要求，这部分可以放心用。

**什么时候能算"天信自己的"**：拿一份所里已结项项目的真实底稿来对一遍，把编号体系、模板章节、表格样式全部替换成所里的。在那之前，这份技能是**"可以照着做的作业框架"**，不是"天信的执业标准"。

## 为什么单独成线

「天信实务知识库」里的 4 张卡（审计准则核心、监管处罚、监管提示、年报审计 SOP）讲的是**判断**，不是**作业**。真正做项目时缺的是：底稿怎么编索引、抽样抽多少、函证发几家、监盘记录写什么、什么时候能出报告。

这份技能只解决作业落地，判断一律指回能力卡——两边不重复维护。

## 还需要所里给的（用来把通用框架换成本所标准）

1. **一份完整的底稿**（某个已结项项目的，客户名可涂掉）—— 看结构、索引体系、复核痕迹
2. **常用表格原件**：函证清单、抽样表、监盘表、截止测试表、调整分录汇总
3. **报告模板**：标准无保留、带强调事项段、保留意见各一份
4. 一句话说明：一个审计项目从接单到归档，谁在哪个环节签字

拿到第 1 项，这份技能就能从"通用框架"升级为"天信自己的作业标准"。

## 已有什么

- 判断骨架（风险导向四步走 / 重要性口径 / 四程序红线 / 意见判定树）**已内联在 `SKILL.md` §一**，不依赖外部卡
- 若所内另装「天信实务知识库」，其 4 张审计卡可作深读补充（可选，非必需）
- 出报告排版用「天信文档与报告」技能，属可选增强，不是审计作业的前置条件
