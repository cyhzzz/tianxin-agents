# 00 天信审计底稿索引体系

> 每个所的底稿编号都不一样，这是天信自己的。索引不连续 = 程序没做 / 没留痕（监管处罚高频雷区，见 `penalties.md`）。

## 一、编号规则

```
ZT-{年份}-{客户简称}-{类}-（{循环}-{序号}）
```

示例：`ZT-2026-某某实业-E5-01`（2026 年某某实业·实质性程序·收入循环·第 1 份）

- 年份：报告期年份
- 客户简称：与业务约定书、报告封面一致（**名称先核实**，简称匹配错企业两版交付物全废）
- 类：见下表 A–H
- 循环/序号：实质性程序（E 类）按循环细分；其余类内从 01 顺序编

## 二、分类（A–H）

| 类 | 名称 | 主要内容 | 关联判断层 |
|---|---|---|---|
| **A** | 总体策略与计划 | 业务约定书、审计计划、重要性计算 | `audit-core` R+M、`audit-sop` 第1–2步 |
| **B** | 了解被审计单位 | 行业/法律/性质/战略/内控了解记录 | `audit-core` R |
| **C** | 风险评估 | 风险识别矩阵、舞弊风险、风险应对 | `audit-core` R、`reg-tips` 舞弊8领域 |
| **D** | 控制测试 | 内控设计评价、控制测试底稿 | `audit-core` P、`reg-tips` 内控段 |
| **E** | 实质性程序 | 按循环分：E1 货币资金 / E2 应收及往来 / E3 存货 / E4 固定资产及在建工程 / E5 收入 / E6 成本费用 / E7 应付及负债 / E8 所得税及权益 / E9 其他 | `audit-core` P 四程序、`cas14`等专项卡 |
| **F** | 特殊项目 | 关联交易、持续经营、期后事项、诉讼仲裁、承诺 | `audit-core` 持续经营、`reg-tips` |
| **G** | 报告与质控 | 试算平衡、未更正错报汇总、报告草稿、质控复核签字页 | `audit-core` O 意见树、`penalties`/`reg-tips` |
| **H** | 综合管理 | 工时记录、复核轨迹、管理层声明书、交接记录 | — |

## 四、勾稽关系（出报告前必查）

- **A-03 重要性** 须被 C 类、E 类、G 类（未更正错报对比）引用，数字一致。
- **C 类风险评估** 须对应到 E 类具体程序的"高风险领域加程序"，不能评了不应对。
- **E 类每张实质性底稿** 须回链到 C 类对应风险点（审计证据指向风险应对）。
- **G 类未更正错报汇总** 须覆盖 E 类所有调整分录（见 `06-常用表格模板.md` 调整分录汇总表）。
- **H 类复核轨迹** 须有项目注师→复核人→合伙人三级签字，无签字 = 未质控。
