# 底稿承接与报告撰写指引（底稿 → 报告映射）

本文件是「热火集工具站 · 会计师」的**主流程文件**。凡用户给出审计底稿与报告模板要求成文审计报告，按本文件流程执行：承接 → 解析模板 → 数据映射 → 成文 → 交付前自查。

> **三条铁律**：模板是唯一格式准绳；底稿审定数是唯一数据源头；底稿证据不支持的意见绝不成文（缺口进"待补清单"退回补程序）。

---

## 一、承接清单（开工前先收齐）

### 1. 审计底稿要件（按需核对，缺项先问）

| 底稿要件 | 用途 | 缺失时的处理 |
|---|---|---|
| 试算平衡表 / 科目余额表（审定数） | 报告引用数字的唯一来源 | 必须补；无法定数字来源不成文 |
| 科目明细表与审定表 | 附注与关键事项数据 | 缺时标注【待底稿补充】 |
| 审计调整分录（及管理层是否接受并过账） | 判定审定数口径 | 必须确认过账状态 |
| 重要性水平计算表 | 关键审计事项选取与错报评价 | 缺时按 `method-parameters.md` 口径提示补 |
| 函证汇总（回函/未回函替代程序） | 意见类型证据支撑 | 缺时提示补程序 |
| 存货监盘记录 | 存货科目证据 | 缺时提示补程序 |
| 关联方清单及关联交易表 | 关联方披露与资金占用排查 | 缺时标注【待底稿补充】 |
| 持续经营评估底稿 | 1324 段成文依据 | 存在疑虑迹象时必须补 |
| 管理层声明书 | 报告日期与证据完备性 | 报告日期不得早于声明书日期 |
| 错报汇总与评价表 | 意见类型判定 | 必须补 |
| 期初余额衔接表 / 上期审计意见 | 首次承接与比较信息（1331/1511） | 首次承接必须补 |
| 期后事项记录 | 期后事项（1332）成文依据 | 缺时提示补程序 |

### 2. 业务信息（缺失必须先问）

- 业务约定书要点：收件人（致送对象）、审计目的、报表期间与基准日、使用范围与使用限制；
- 上期审计意见（意见类型、非标事项、强调事项）；
- 意见类型预期（仅作沟通起点，最终依底稿证据判定，**不得预设倒推**）；
- 签章信息：事务所名称/地址、签字注册会计师（占位即可，不代签）。

## 二、模板解析（模板是唯一格式准绳）

1. **拆槽位**：把模板拆成"固定文本 + 待填槽位"，输出槽位清单表：

   | 槽位名 | 位置（章节） | 数据来源 | 填写口径 | 回填状态 |
   |---|---|---|---|---|

2. **模板有的不臆造，模板没有的不删改**：模板中不适用的槽位，提示用户确认是删除还是保留空槽；模板没有但 CSA 1501 要求的要素（如"形成审计意见的基础"段），提示用户补充，经确认后加入。
3. **不改样式**：不改动模板的编号、顺序、措辞风格；自身知识库与模板不一致时，先提示差异点，由用户确认后按模板执行。
4. **槽位回填率**：交付时报告所有槽位 100% 回填，无【待填】/【TODO】残留；确实无数据的留【待底稿补充】并在待补清单列明。

## 三、底稿 → 报告数据映射

| 报告内容 | 底稿来源 | 映射要点 |
|---|---|---|
| 审计意见段（编制基础表述） | 会计政策/编制基础审定表 | 与被审计单位实际执行的准则一致，不得写错准则名称 |
| 审计意见类型 | 错报汇总与评价表 + 范围受限记录 | 按 CSA 1502 判定；判定过程先与用户确认 |
| 形成审计意见的基础段 | 程序执行记录 | 非无保留意见须写明原因与影响金额/范围，不得仅写"详见附注" |
| 关键审计事项段（1504） | 重要性水平表 + 特别风险评估 + 错报评价 | 聚焦最重大事项（语料高频：收入确认、重大资产/商誉减值）；审计应对可索引底稿索引号 |
| 持续经营重大不确定性段（1324） | 持续经营评估底稿 | 与管理层改善计划、报表披露三方互证 |
| 强调/其他事项段（1503） | 期后事项、比较信息、上期意见记录 | 不得替代非无保留意见；写明"不影响已发表的审计意见" |
| 责任段（管理层/注册会计师） | 固定文本 + 编制基础 | 按模板与 1501 口径 |
| 审计依据章节 | `standards-and-regulations.md` 写法 A/B/精简版 | 文号现行有效，施行日核查 |
| 报告日期与签章 | 管理层声明书日期、业务约定信息 | 报告日期 ≥ 声明书日期且 ≥ 报告批准报出前证据获取日 |

**数字规则**：报告所有数字引底稿审定数，禁止手工改动；审定数→报告列报数、调整前→调整后等口径转换，给出换算表。

## 四、报告成文顺序

1. **判定意见类型**（底稿证据 → CSA 1502），与用户确认后再动笔；
2. **按模板顺序逐段成文**：标题 → 收件人 → 审计意见 → 形成审计意见的基础 → 关键审计事项 → 持续经营/强调事项段 → 管理层与治理层责任段 → 注册会计师责任段 → 其他报告责任（如适用）→ 审计依据章节（模板有则按模板位置）→ 签章落款 → 报告日期；
3. **段落逻辑互证**：意见段 ⇄ 形成基础段 ⇄ 关键审计事项/强调事项段不得矛盾（见 `report-outline.md`）。

## 五、交付前自查清单（勾稽与要素）

**要素级**（详表见 `report-outline.md` 第九节）：

- [ ] 模板槽位 100% 回填，无【待填】/【TODO】残留
- [ ] 标题、收件人、报告日期、签名盖章、事务所名称地址盖章齐全
- [ ] 意见段 ⇄ 形成基础段 ⇄ 关键审计事项/强调事项段逻辑一致
- [ ] 非无保留意见的"基础"段写明原因与影响金额/范围

**数字勾稽**（报告 ⇄ 底稿审定数逐项抽勾）：

- [ ] 营业收入、净利润、总资产、净资产四项必勾
- [ ] 审计调整前后数口径一致，换算表可复核
- [ ] 报告日期 ≥ 管理层声明书日期

**依据级**：

- [ ] 审计依据文号现行有效（按 `standards-and-regulations.md` 时效核查）

**监管级**：

- [ ] 按 `inquiry-focus-points.md` 前置核查清单逐项排查，薄弱点已列入提示

## 六、待补清单机制（证据缺口处理）

撰写中发现以下情形，一律记入"待补清单"退回补程序，**不得为成文而编造或臆测**：

- 数字无底稿来源 → 待补审定数；
- 程序无记录（函证/监盘/替代程序缺失）→ 待补程序证据；
- 意见类型证据不足 → 待补错报评价或范围受限说明；
- 文号无法核实 → 待核现行有效文本，标注【未检索到】。

待补清单格式：**事项 / 缺口描述 / 影响的报告段落 / 建议补法**。
