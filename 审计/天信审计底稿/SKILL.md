# 天信审计底稿

我是天信审计项目的"作业台"。判断骨架（风险导向四步走、重要性口径、四程序红线、意见判定树）已内联在 §一，本技能**不依赖任何其他技能**，专解决一个县城所天天被卡住的问题：

> 计划怎么写、风险怎么落到纸上、函证发几家怎么控制、监盘记录写什么、抽样抽多少、底稿怎么编索引、什么时候能出报告、质控页谁签字。

这些每个所的做法都不一样，天信用自己的模板。

## 一、判断骨架：风险导向四步走（内联，不依赖其他技能）

审计不是把账翻一遍，是**证明风险已被合理应对**。四步缺一不可：

| 步 | 做什么 | 输出 | 落到哪份底稿 |
|---|---|---|---|
| **R 风险评估** | 了解被审计单位及其环境（行业、业务、内控），识别报表层次与认定层次重大错报风险 | 风险清单 | `references/02` |
| **M 重要性** | 定整体重要性（常用营业收入 0.5%–5% 或总资产 × 比例，须记录选定理由）；实际执行重要性取整体的 50%–75% | 重要性计算表 | `references/01` |
| **P 进一步程序** | 函证 / 监盘 / 截止 / 分析四类，按风险评估结果分配资源 | 程序记录与证据 | `references/03`、`references/04` |
| **O 意见形成** | 综合已更正与未更正错报、范围是否受限，判定报告类型 | 意见判定表 | `references/05` |

### 四程序的红线（监管处罚的高频点）

- **函证**：审计人员**直接控制**收发，不得由被审计单位代劳；回函不符必追查；**未回函须做替代程序**（期后收款、销售与收款凭证、发货记录），不得仅以未回函结案。
- **监盘**：实地、突击、留影像。
- **截止测试**：收入费用是否计入正确期间，防跨期。
- **分析程序**：趋势与比率异常是线索，不是结论。

### 意见判定树（速查）

| 情形 | 意见类型 |
|---|---|
| 报表公允、范围不受限 | 无保留（标准 / 带强调事项段） |
| 个别事项重大但不广泛 | 保留 |
| 错报重大且广泛 | 保留或否定（看影响广度） |
| 范围受限重大且广泛、无法取得充分适当证据 | 无法表示意见 |

### 持续经营

准则要求评估被审计单位持续经营能力（通常展望 12 个月）。连续亏损、资金链紧的客户必做，
存在重大不确定性时在报告中单设段落说明——这一条最容易漏，也最容易出事。

> 若所内另装了「天信实务知识库」，可深读其中的审计卡（六步流水线、监管处罚五道防线、监管提示三清单）。
> **不装也能按上面这套干完一个年报审计**——本技能不依赖它。

## 二、工作流（2 个前置判断 + 5 步闭环）

**开工前先做两个判断，做错了后面全白干**：

| # | 判断 | 走哪 |
|---|---|---|
| 0.1 | **这单该不该接**：目的与用途、管理层诚信、我们有没有能力、独立性、收费能否覆盖 | `references/08-承接与独立性.md`（五问 + 背景核查 + 约定书 12 项 + 解除情形） |
| 0.2 | **是不是专项**：委托目的是"某个特定认定/口径"，不是"整体报表公允性" | `references/07-专项审计骨架.md`（验资 / 高新 / 专项资金 / 清算 / 经责），**不套年报底稿** |

判断完再进 5 步闭环。四个核心交付 = 审计计划 / 风险评估 / 审计程序 / 工作底稿 Checklist：

1. **审计计划**（对应 §一的 R + M）→ `references/01-审计计划模板.md`：准则适用、时间人员、风险清单、重要性计算、总体策略。
2. **风险评估工作底稿**（对应 §一的 R）→ `references/02-风险评估工作底稿.md`：了解被审计单位问卷、风险识别矩阵、舞弊风险识别。
3. **进一步审计程序（四程序）作业 Checklist**（对应 §一的 P）→ `references/03-四程序作业Checklist.md`：函证（控制+替代）、监盘（计划+记录+影像）、截止、分析；抽样量见 `references/04-抽样量指引.md`。**拟信赖内控的**，另做控制测试 → `references/09-控制测试底稿.md`（五要素留痕 / 穿行测试 / 控制矩阵 / 偏差评价）。
4. **底稿索引体系** → `references/00-底稿索引体系.md`：天信自己的编号/分类（A–H 类）。每个所不同，这是天信的。
5. **报告与质控工作底稿**（对应 §一的 O）→ `references/05-报告与质控工作底稿.md`：意见判定表、强调/持续经营段决策、质控复核签字页。

## 三、上手方式

拿到一户审计任务，按上面 1→5 顺序走，每一步打开对应 reference 复制模板填。常用表格（函证清单、抽样表、监盘表、截止测试表、调整分录汇总表）统一在 `references/06-常用表格模板.md`。

## 四、红线（沿用项目 AGENTS.md，逐条适用）

- **事实与推演分离**：底稿里客户提供的数标【事实】，我们测算/估计的标【推演】，不混写。
- **不编造准则与处罚**：不杜撰文号、比例、案例。记不清就写明"待查准则原文"，不要编一个看起来合理的数。
- **不替代 CPA 判断**：本技能出模板、Checklist、索引；结论、抽样最终量、意见类型、签字由项目注师负责。所有产出默认带「待复核」。
- **红线即作业项**：§一 的四程序红线不是"读读而已"，要落进对应底稿和质控页逐项勾。
- **底稿索引必须连续可追溯**：无索引 = 没做（监管处罚高频源于程序没做/没留痕）。

## 五、出版物

底稿/报告最终排版走「天信文档与报告」Skill 的五轨（Word / A4 PDF / 网页长页 / 演示 deck / Excel 表）；底稿表格（抽样表、控制矩阵、勾稽表）走它的 Excel 轨道。本技能只负责内容骨架与勾稽，不负责版式。

## 反馈与改进

这份技能是 [cyhzzz/tianxin-agents](https://github.com/cyhzzz/tianxin-agents) 的**副本**。
**你在这里的修改不会自动回到仓库**——会话一结束就没了。

遇到下面任一情况，请留下改进提案，不要只在会话里绕过：

- 内容有误、政策已变、数字对不上
- 缺了某一类常见情形，你只能临场发挥
- 用户纠正了你，而纠正的内容本该写在这份文件里

### 优先：能改就直接改文件，再回传

AI 遇到技能有问题，默认做法是临场绕过——这次能用，下次还是错的。
**更好的做法是直接改 `~/.workbuddy/skills/天信审计底稿/` 下的文件**，然后告诉用户：

> 我改了「天信审计底稿」里的 `references/xx-yyy`，改动还没回仓库。
> 克隆 https://github.com/cyhzzz/tianxin-agents 后跑这一条就能提 PR：
> `python contribute.py --from-installed ~/.workbuddy/skills/天信审计底稿`

这条路径最有用——它产生的是**可以逐行 review 的真实改动**，不是一段描述。

### 改不了时才交提案

政策拿不准、超出权限、只是觉得表述不清——写成文件再告诉用户：

    # 改进提案：天信审计底稿 · 内容有误

    | 字段 | 内容 |
    |---|---|
    | 技能 | 天信审计底稿 |
    | 类型 | 内容有误 |
    | 位置 | references/xx-yyy.md 第 12 行 |

    **现在怎么写的**：（原文照抄，别转述）
    **应该是**：（改成什么）
    **依据**：（政策文号 / 准则条款）

存到 `~/.workbuddy/skills/_待提交改进/天信审计底稿-<主题>.md`，然后告诉用户跑
`python contribute.py --proposal <该文件>`。没有 git 也能反馈——
去仓库开 issue 把上面这段贴进去就行。

**政策类改动必须给文号。** 没有文号的税率、优惠比例一律不收：
一份过期税率表会让客户少缴、补税加滞纳金，这种错仓库里出过六处。
**提案里不要写客户名、税号、金额**——那是公开仓库。
