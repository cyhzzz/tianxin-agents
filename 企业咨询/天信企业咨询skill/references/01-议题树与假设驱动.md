# 01 议题树与假设驱动

> 天信原创。上游两个管理包（王老师 33 份 + 企效通 11 份）覆盖 16 个管理模块与中小企业 8 大能力域，材料很厚，
> 但**缺一套"从哪里下手"的方法**——拿到一个模糊的委托（"帮我们看看怎么增长""人效怎么提"），容易直接开始翻资料、套模板。
> 本文件补的是**议题树 + 假设驱动**这套咨询作业法。它不产出观点，产出的是"该验什么"。

## 一、先想清楚：咨询作业不是资料整理

| 做法 | 结果 |
|---|---|
| 资料驱动：客户给什么看什么，看完写总结 | 报告很长，结论是"公司存在几个问题"，客户看完不知道该干嘛 |
| **假设驱动**：先猜答案，再去找证据推翻或证实 | 结论少而硬，每条都有证据，客户知道下一步做什么 |

**顺序**：定问题 → 拆议题 → 立假设 → 找证据 → 出结论。**不是**先看资料再想问题。

## 二、议题树：三层，每层都要过 MECE

```
核心问题（一句话，可判断真假）
├── 议题 1 —— 假设 1.1 —— 验什么
│            —— 假设 1.2 —— 验什么
├── 议题 2 —— 假设 2.1 …
└── 议题 3 …
```

**示例**（"今年利润掉了 30%，为什么"）：

| 议题（第一层） | 假设（第二层） | 怎么验 |
|---|---|---|
| 收入端 | 主力产品销量下滑 | 分产品月度销量、客户流失清单 |
| | 价格被压 | 单价趋势、合同对比、同行报价 |
| | 客户结构恶化（小单多、大单少） | 客户分层收入占比、单客年均 |
| 成本端 | 原材料涨价未传导 | 采购单价 vs 售价涨幅、调价条款 |
| | 人工成本上升（人数/薪资/社保） | 人均产出、社保基数变化 |
| | 制造费用摊薄不足（产量下降） | 产量与固定成本、单位制造费用 |
| 费用端 | 销售费用投放效率下降 | 获客成本、转化率、区域对比 |
| | 一次性支出（罚款、赔偿、改造） | 明细账、非经常性损益 |

**MECE 检验三问**：

1. **有没有漏**？（收入、成本、费用之外，还有税、投资收益、资产减值——别忘）
2. **有没有重**？（"成本高"和"毛利低"是一回事，不能并列）
3. **能不能判断真假**？（"管理不好"不是议题，无法验证；"审批链过长导致交付延期"才是）

## 三、假设要写成"可被推翻的句子"

| 不合格 | 合格 |
|---|---|
| 公司管理有待提升 | 订单交付周期超过 45 天的比例从 12% 升到 34%，原因是排产靠人工、无产能看板 |
| 人力成本偏高 | 直接人工人均产出同比下降 18%，同期人数增加 22% |
| 市场环境不好 | 同区域同行营收增速 +5%，本公司 −12%，差异集中在两个大客户流失 |

**写法**：`现象（有数） + 原因（可查） + 若成立应看到什么`。

## 四、证据分级（每条结论后面标等级，客户才敢用）

| 级 | 来源 | 用法 |
|---|---|---|
| **A** | 客户系统/账簿原始数据（ERP、财务账、工资表、银行流水） | 可直接下结论 |
| **B** | 一手访谈、现场观察（我们自己问的、看的） | 可下结论，标注"访谈所得，未经系统验证" |
| **C** | 客户提供的汇总表、PPT、口头转述 | 只能作线索，**不能作结论依据** |
| **D** | 公开资料、行业报告、我们的经验 | 作对标与假设来源，不当证据 |

**红线**：C 级当 A 级用，是咨询报告最常见的翻车方式——客户一句"大概三十来个点"，写进报告变成"毛利率 30%"，一查账是 22%。

## 五、假设翻转测试（每份报告至少做一次）

对**支撑结论的那条假设**，问三个问题：

1. 什么证据会让我推翻它？
2. 这个证据我有没有？没有的话，结论要降级（"可能""初步判断"）。
3. 如果它被推翻，结论还成立吗？如果不成立，就不能写成定论。

**示例**：结论"亏损主要来自低毛利订单"→ 翻转测试："如果这些订单实际毛利不低，只是费用分摊错了呢？"→ 去查分摊口径 → 发现分摊按收入比例、未按工时分摊 → 结论改成"成本核算口径失真，需先修正分摊再判断"。

**这一条比什么都值钱**：它防止我们把"客户想听的答案"包装成"分析结论"。

## 六、作业节奏（一个小项目 3–4 周）

| 周 | 干什么 | 交付 |
|---|---|---|
| 第 1 周 | 定核心问题 → 建议题树 → 立假设 → 列数据清单 | **一页议题树**（给客户确认"是不是这些事"） |
| 第 2 周 | 取证：要数、访谈、现场看 | 证据表（每条假设 → 证据 → 等级） |
| 第 3 周 | 收敛：证实/推翻，补关键缺口 | 结论清单（不超过 5 条） |
| 第 4 周 | 成文：结论 → 依据 → 建议 → 落地条件 | 报告（走文档技能出版） |

**第 1 周那一页议题树必须给客户看**：客户看完常说"第 3 条不是问题，第 5 条才是"——省下两周。

## 七、一页议题树模板（可直接用）

| 核心问题 | 议题 | 假设 | 需要的证据 | 证据等级目标 | 状态 |
|---|---|---|---|---|---|
| （一句话） | 收入端 | 主力产品销量下滑 | 分产品月度销量 | A | 待验/证实/推翻 |
| | 成本端 | 原材料涨价未传导 | 采购单价 vs 售价 | A | |
| | 费用端 | 销售费用效率下降 | 获客成本、转化率 | A/B | |

**边界**：本文件只给"怎么想"。具体模块的打法（战略解码、组织管控、薪酬设计、流程优化）在上游 `mc-*`；中小企业落地的模板与指标在上游 `sme-*`。

> **红线**：不编数据、不编同行基准。行业数据找不到就写"未取得可比数据，按客户历史趋势判断"——这比编一个"行业平均 15%"诚实，也更经得起追问。
