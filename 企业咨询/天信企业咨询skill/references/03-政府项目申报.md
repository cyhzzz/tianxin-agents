# 03 政府项目申报

> 天信原创。上游管理包有战略、组织、营销、财务，**没有一条讲政府项目申报**——而县城企业的真实需求里，"帮我报个专精特新/技改补贴"出现的频率远高于"帮我做战略规划"。
> 本文件讲**怎么组材料、怎么核数、怎么不翻车**。**具体条件、比例、时限以当年当地通知为准，不凭往年经验套。**

## 一、申报的本质：不是写材料，是凑证据

申报失败，九成不是"材料写得不好看"，是**硬条件不满足**或**数据前后打架**。所以顺序是：

```
政策匹配 → 硬条件自评 → 缺口补救（来得及才报）→ 证据组织 → 数据勾稽 → 现场核查准备
```

**先做能不能报的判断，再谈怎么写**——反过来做，写完发现差 0.3 个点，白干三周。

## 二、政策匹配五问（每一条都要有出处）

| 问 | 去哪找 |
|---|---|
| 谁受理、归口哪个部门 | 经信、科技、发改、人社、农业农村、市场监管（不同项目不同口） |
| 什么类型、什么层级 | 国家级 / 省级 / 市级 / 县（区）级；认定类 / 奖补类 / 试点类 |
| **硬条件是什么** | 当年申报通知 + 管理办法原文（**逐条摘出来做成表**） |
| 截止时间与批次 | 通知里的截止日；有的按季度、有的常年受理 |
| 去年谁报了、报了多少 | 公示名单（最有价值：看同行什么水平能过） |

**方法**：把通知里的条件逐条抄成一张"条件对照表"，左列条件原文，右列客户现状，第三列填"满足/不满足/需佐证"。这张表决定报不报。

## 三、常见可申报类型（浙江/台州企业常问的）

| 类型 | 常见叫法 | 核心看什么 |
|---|---|---|
| **梯度培育** | 创新型中小企业 → 专精特新中小企业 → 专精特新"小巨人" | 研发投入、知识产权、主营专注度、增长率（梯度管理依据《优质中小企业梯度培育管理暂行办法》，工信部企业〔2022〕63号） |
| **技术改造** | 技改项目奖补、设备更新补贴 | 设备投资额、发票与付款、投产时间、节能量/智能化水平 |
| **研发投入** | 研发费用后补助、研发机构认定 | 研发费用归集（与加计扣除口径可能不同）、研发项目立项与验收 |
| **创新平台** | 企业技术中心、工业设计中心、重点实验室 | 研发人员、设备原值、成果数量 |
| **绿色低碳** | 绿色工厂、清洁生产、节能诊断 | 能耗指标、体系认证、改造投入 |
| **数字化** | 两化融合、智能工厂、上云 | 系统投入、数据打通程度、上云合同 |
| **农业与乡村** | 农业龙头企业、产业强镇、地理标志 | 产值、带动农户数、基地规模 |
| **人才类** | 各类人才计划、博士后工作站 | 人才层次、薪酬、项目 |

**判断依据一律以当年通知为准**：同一个名目，每年条件会调（研发费用比例、增长率门槛、知识产权数量），拿去年文件套今年必错。

## 四、条件自评：把"硬条件"和"加分项"分开

| 类别 | 例子 | 处理 |
|---|---|---|
| **硬条件**（不满足就没戏） | 成立年限、营收规模、研发费用占比、知识产权数量、无重大违法记录 | 一条不满足，**先算能不能在截止前补上**；补不上就不报 |
| **加分项**（影响排名） | 参与标准制定、省级以上奖项、产学研合作、数字化水平 | 有就写，没有不编 |
| **否决项**（一票否决） | 安全/环保/税务重大违法、失信被执行、数据造假 | 先查信用中国与执行信息 |

**"无重大违法记录"必须自查**：信用中国、国家企业信用信息公示系统、税务处罚、环保处罚、安全生产处罚。有记录的不报，报了也是浪费。

## 五、材料结构与证据链

一份申报材料通常四块，**每块都要能互相印证**：

| 块 | 内容 | 谁出 |
|---|---|---|
| 1. 申请书 | 企业基本情况、经营数据、项目内容、预期效益 | 我们协助撰写，企业盖章 |
| 2. 专项审计报告 | 研发费用、项目投资额、营收等**特定口径**的审计 | 事务所出具（**这就是我们的活**） |
| 3. 佐证材料 | 营业执照、专利证书、合同、发票、付款凭证、验收报告、体系认证、纳税证明 | 企业提供，我们核完整性 |
| 4. 承诺书 | 材料真实性承诺、无违法记录承诺 | 企业法定代表人签 |

**证据链的逻辑**：申请书里写的每个数，都要能追到"合同 → 发票 → 付款 → 入账 → 报表"。**追不到的数，删掉，不要圆。**

## 六、数据勾稽：三处必须一致

| 比对 | 常见不一致 |
|---|---|
| 申请书 vs 专项审计报告 | 研发费用、项目投资额口径不同（一个按发票、一个按入账） |
| 专项审计报告 vs 纳税申报表 | 营收不一致（有未开票收入、视同销售） |
| 佐证发票 vs 银行流水 | 只有发票没付款，或付款给第三方 |
| 人员数 vs 社保缴纳 | 申请书说 80 人，社保只缴 45 人 |

**做法**：做一张"数据一致性对照表"，逐项列出申请书数、审计数、申报表数、差异、原因。**差异有正当理由的写清，没有的回去改数**——现场核查最先问的就是这个。

## 七、现场核查准备（很多项目会来）

- 研发场所、设备、研发人员是否在位（**名单上的人当天要在**）
- 研发项目立项书、任务书、过程记录、验收报告是否齐全
- 专利证书原件、软件著作权登记证书
- 项目投资的设备是否在厂、铭牌与发票型号是否一致
- 财务账套能否当场调出对应凭证

**建议**：核查前一周做一次"模拟核查"，按上面的清单走一遍，缺什么补什么。

## 八、常见失败原因（按出现频率）

1. **硬条件差一点**（研发费用占比、增长率、知识产权数），靠"调整口径"硬凑——**这是造假，不做**。
2. **研发项目与主营无关**（做五金的企业报了个"AI 算法"项目），评审一看就否。
3. **知识产权与产品不匹配**（买的专利、与主营无关的软著）。
4. **数据三处不一致**（申请书、审计报告、纳税申报表）。
5. **发票与付款对不上**（只有发票、没付款，或付给关联方）。
6. **材料缺件**（少一个盖章页、少一份验收报告），形式审查就被退回。
7. **错过批次/时限**（等材料齐了，窗口关了）。

## 九、和审计、税务的接口

- **专项审计**（研发费用、投资额）→ 走审计线 `天信审计底稿` 的专项骨架，按申报口径出报告，**不套年报底稿**。
- **研发费用归集**：高企认定口径 ≠ 加计扣除口径 ≠ 后补助口径，**三套口径不能混**（见审计线 `references/07-专项审计骨架.md`）。
- **纳税申报数据**：以电子税务局为准，申报表与账不一致的，先解决账，再报项目。

## 十、红线

- **不造假、不"包装"**：虚增研发费用、编造项目、PS 发票，是骗取财政资金，性质比逃税更重。
- **不承诺结果**：能不能过由主管部门定，我们只负责"把真实情况组织成合规材料"。
- **收费不与结果挂钩**：不按"获批金额分成"，那是违规的中介模式。
- **不接明知不满足条件的**：帮客户"试试看"可以，但必须书面告知硬条件缺口与失败风险。
- 客户信息（项目金额、研发内容）属商业秘密，不进示例、不进公共仓库。

> **一句话**：申报是**把真实的好，用主管部门看得懂的方式摆出来**；不是把不够的好，装扮成够。
