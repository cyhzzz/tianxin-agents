# 08 · 经验萃取 · 知识体系构建 · 数字化转型

## 一、经验萃取

### 萃取对象识别（四类高价值经验）

| 类型 | 来源 | 价值 |
|---|---|---|
| 最佳实践 | 业绩最好的个人/团队 | 可复制的成功套路 |
| 关键事件 | 重大成功或失败的项目 | 决策与风险教训 |
| 隐性诀窍 | 老师傅、金牌销售的手感 | 难以言传的判断力 |
| 流程规范 | 高频重复性工作 | 一致性保障 |

### 萃取五步法

1. **选对象**：选绩效前 10% 或关键岗位，明确萃取主题（如"大客户破冰"）
2. **访专家**：用 STAR 与关键事件法提问——"当时什么情况？你怎么判断？做了什么？结果如何？为什么这么做？"
3. **抽结构**：把零散叙述整理为"场景 → 判断依据 → 动作 → 结果 → 适用边界"
4. **验真伪**：请第二、第三位专家验证，剔除个人运气与特权因素
5. **成标准**：产出 SOP / 案例 / 检查清单 / 微课，并组织试讲试用

### 提问清单（萃取访谈用）

- 这类事你一年做多少次？典型的和最难的各是什么样？
- 你第一步先看什么？最怕什么情况？
- 有哪些"外行看不出来"的信号？
- 什么情况下你的方法会失效？
- 如果带新人，你会让他先练哪一步？

### 萃取成果形式

| 形式 | 适用 | 关键要求 |
|---|---|---|
| SOP | 高频、可标准化 | 步骤化、有判断分支、有检查点 |
| 案例库 | 判断力类、销售类 | 情境完整、含失败与反思 |
| 检查清单 | 易遗漏、高风险 | 条目化、可勾选、有标准 |
| 微课 | 需要讲解的逻辑 | 10–15 分钟、配练习 |
| 知识地图 | 整体知识架构 | 分层、有依赖关系 |

## 二、企业知识体系构建

### 知识分类框架

| 层级 | 内容 | 载体 |
|---|---|---|
| 制度层 | 规章、办法、权限 | 制度文件库 |
| 流程层 | 流程图、SOP、表单 | 流程文件库 |
| 标准层 | 技术标准、检验标准、作业标准 | 标准库 |
| 经验层 | 案例、最佳实践、复盘记录 | 案例库 |
| 学习层 | 课程、教材、题库 | 培训库 |
| 数据层 | 指标定义、口径说明、报表模板 | 数据字典 |

### 知识体系构建四步

1. **盘点**：现有文件清点、分类、去重，识别缺口（"哪些岗位的工作没有文档支撑？"）
2. **架构**：按"职能域 × 知识层级"搭建目录树，统一命名与编号规则
3. **生产**：责任到人（每个知识域有 owner）、更新周期明确、审核人明确
4. **运营**：检索入口、使用激励、更新机制、考核挂钩（如"制度覆盖关键岗位率"）

### 命名与版本规范建议

```
【类型】-【职能域】-【主题】-V【主版本.次版本】-【生效日期】
示例：SOP-生产-注塑换模-V2.1-20260901
```

### 知识管理落地机制

| 机制 | 做法 |
|---|---|
| 责任机制 | 每类知识有 owner，纳入岗位职责 |
| 更新机制 | 触发式（流程变更、事故后、年度）+ 定期式 |
| 使用机制 | 新人必修、考核关联、搜索优先 |
| 激励措施 | 贡献者署名、积分、与晋升挂钩 |
| 淘汰机制 | 定期清理过期文件，标注失效 |

## 三、数字化转型规划与推进

### 1. 成熟度自评（五级）

| 级别 | 特征 |
|---|---|
| L1 手工 | 纸质/Excel 为主，数据分散 |
| L2 单点信息化 | 财务或进销存单一系统，数据孤岛 |
| L3 系统集成 | 核心业务系统打通（ERP+OA），数据统一 |
| L4 数据驱动 | 有 BI 看板与指标体系，决策看数据 |
| L5 智能运营 | 预测性分析、算法辅助决策、自动化流程 |

> 中小企业多数处于 L1–L2，**不要跳过 L3 直接谈 AI**。

### 2. 场景清单与优先级（按 ROI 排序）

| 场景 | 典型收益 | 难度 | 优先级 |
|---|---|---|---|
| 财务+进销存一体化 | 账实一致、库存可视 | 中 | ★★★ |
| 生产报工与工序进度 | 交期可视、计件准确 | 中 | ★★★ |
| 采购与供应商协同 | 交期可控、比价留痕 | 中 | ★★ |
| CRM 与销售漏斗 | 商机不丢、过程可控 | 低 | ★★★ |
| 电子审批与 OA | 效率、留痕 | 低 | ★★★ |
| BI 经营看板 | 决策效率 | 中 | ★★ |
| 质量追溯（条码/二维码） | 召回与追溯 | 中高 | ★★ |
| MES / 智能排产 | 产能与效率 | 高 | ★（视规模） |
| 设备物联与预测性维护 | 减少停机 | 高 | ★ |

### 3. 系统选型要点

| 维度 | 考察问题 |
|---|---|
| 业务匹配 | 是否支持你的核心流程（工艺路线、委外、多单位、批次） |
| 扩展性 | 能否随业务增长扩展模块与用户 |
| 实施能力 | 服务商的行业经验、实施团队稳定性、本地服务 |
| 总拥有成本 | 许可 + 实施 + 硬件 + 培训 + 年度维护 + 二次开发 |
| 数据主权 | 数据可导出、接口开放、私有化可能性 |
| 失败风险 | 要求考察同行业同规模案例的实际使用情况 |

### 4. 实施路线图（12–18 个月示例）

| 阶段 | 周期 | 内容 | 里程碑 |
|---|---|---|---|
| P1 诊断规划 | 1–2 月 | 流程梳理、主数据标准、选型 | 蓝图与预算获批 |
| P2 上线核心 | 3–6 月 | 财务+进销存/OA 上线 | 账实一致、审批线上化 |
| P3 业务深化 | 4–6 月 | 生产报工/CRM/采购协同 | 交期与商机可视 |
| P4 数据驱动 | 3–6 月 | 指标体系 + BI 看板 | 经营看板月度运行 |
| P5 智能探索 | 持续 | 预测、自动化、AI 应用 | 单场景 ROI 验证 |

### 5. 数字化转型常见失败原因（必须提示）

1. **先上系统再理流程** → 把混乱固化
2. **主数据没治理** → 物料、客户、供应商编码混乱，报表永远不准
3. **老板不参与** → 变成 IT 部门的项目
4. **预算只算软件不算实施** → 中途缺钱停摆
5. **不做培训与考核** → 数据录入随意，系统变摆设
6. **贪大求全** → 一次上全部模块，项目超期失控
7. **指标不定义** → 同一个"毛利率"三个部门三种算法

### 6. 投入产出测算模板

| 项目 | 年化收益/成本 | 说明 |
|---|---|---|
| 人力节省 | +X 万元 | 减少的重复录入/统计工时 × 人工成本 |
| 库存资金占用下降 | +X 万元 | 库存周转天数改善 × 日均成本 × 资金成本率 |
| 交期违约损失减少 | +X 万元 | 历史违约赔付与客户流失估算 |
| 系统总成本 | −X 万元 | 许可+实施+硬件+维护+人力 |
| **净收益 / 回收期** | | 一般中小企业期望回收期 ≤ 24 个月 |

> 测算必须写明假设，并对关键假设做敏感性分析。
