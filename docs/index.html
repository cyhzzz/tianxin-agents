01

它是什么：一个库，七本手册

不是一套软件，是所里作业规矩的书面版。

十本分三组：公用三条谁都用得上（出文档、查实务判断、查准则原文）；业务线一共七条——审计、税务、代账、会计核算、资产评估、企业咨询、绩效评价；运营一条是服务获客的日报，全所都用得上。你说的话决定它翻哪本，翻错了换句话再要一次就行。

这些手册的做法，是从外面一批成熟的行业专家经验里抽出来，再结合天信所里的实际情况整理成册。外面那部分，是一字未改收进来的行业通行做法和准则；所里这部分，是我们自己总结的作业规矩，以及用真实报告做的样例。

为什么不做成十一个独立的东西

所里十几个人，业务是交叉的：做审计的也接代账，代账的遇到报表问题要查审计准则。拆成十一个入口，每次都得先想“我这个问题算哪条线”，想错了就调不到。合成一个库，靠你说的话来判断，反而少一道工序。

02

怎么开始用

三步，只有第一步需要动手。

整套东西已经装好（或由 AI 替你装），你不用记命令、不用点菜单。新开一个对话，照平时的说法把事说一遍就行；装完要新开对话，技能才会加载——这一步漏了，会觉得“装了没用”。

克隆 https://github.com/cyhzzz/tianxin-agents 到本地，进仓库根目录读 START-HERE.md，按里面的默认装法装好（全部技能装全局 + WorkBuddy 下加装专家，装完问我一句要不要开日报定时任务），跑 python install.py --verify 验收，最后告诉我另外几种装法分别在什么时候该换成。

04

现在能用到什么程度

这一节最该看：哪条能直接上活，哪条还只是骨架。

判断标准很简单——有没有在所里的真实材料上跑过。七条业务线里，审计、会计核算、绩效评价已经用真实报告校准过，其余四条还是草稿；资产评估文件最大，但九成是收来的准则原文，不是所里的东西。

资产评估 方法选型、价值类型、现场核查、报告审核有骨架——底子是收来的评估准则与一份外部（坤元）报告样本；本所未开展工程造价；公开渠道未找到天信自出的评估报告，真实项目参数还没用所里项目校准。 草稿
绩效评价 指标设置、打分表、报告模板——绩效专家经验已收，所里补了天台本地口径和一份本所部门整体实例；已用省表式与本所实例校准过，但完整报告还没在一家单位上整轮跑过。 已校准

这两条之所以能用，不是因为写得漂亮，是因为都在真实材料上返工过几轮——每一条规则背后都有一次具体的失误。

05

它做不到什么

这几条写清楚，比宣传它能干什么更重要。

  • 七条业务线都是草稿；审计、会计核算、绩效评价已用真实报告校准，但都还没在所里真实项目上整轮跑过，其余四条仍是纯草稿。拿它当“该怎么走”的提示可以，当成品交出去不行。
  • 不替代 CPA 判断。它给框架、给格式、给该问客户要什么材料；签字和结论是人负责。
  • 不承诺合规。审计报告要素齐不齐，最终以执业准则和所内质控为准，不以它输出为准。
  • 陈版主问答靠线上服务。服务停了它会如实报错，不会拿训练数据冒充最新答疑——这点比“答得出来”重要。
  • 日报的筛选还在调。抓得到不等于筛得准，头几天建议每天扫一眼标题，觉得偏了就说“这条以后别推”。

所以现阶段最好这么用：写报告、排稿子、要情报，直接找它；七条业务线都是草稿，先让它理思路、列清单、提醒该要什么材料，成品还是自己从头走一遍。等哪条线把所里的真底稿、真客户资料喂进去，再谈“能不能直接交”。
