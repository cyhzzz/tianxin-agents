# 方式一 · 全局安装

装一次，这台机器上所有对话都能用。

---

## 步骤

```bash
git clone https://github.com/cyhzzz/tianxin-agents.git
cd tianxin-agents
python install.py --list      # 先看探测到的目录对不对
python install.py --global
```

装完**必须新开一个对话**，技能才会被加载。已开着的会话不会热更新。

---

## 它装到哪

自动按这个顺序探测，用第一个存在的：

| 优先级 | 平台 | 目录 |
|---|---|---|
| 1 | WorkBuddy | `~/.workbuddy/skills/` |
| 2 | Claude Code | `~/.claude/skills/` |
| 3 | Codex CLI | `~/.codex/skills/` |
| 4 | Gemini CLI | `~/.gemini/skills/` |
| 5 | OpenCode | `~/.config/opencode/skills/` |

探测不到就显式指定：

```bash
python install.py --global --target workbuddy
python install.py --global --target ~/my-agent/skills     # 任意路径
```

**探测顺序可能选错**：如果你同时装了 WorkBuddy 和 Claude Code，它只会装到 WorkBuddy。要两家都装，跑两次：

```bash
python install.py --global --target workbuddy
python install.py --global --target claude-code
```

---

## 装完长什么样

```
~/.workbuddy/skills/
├── README.md               ← 安装器写的来源说明，别删
├── 天信文档与报告/
│   ├── SKILL.md
│   ├── references/         10 份方法论
│   ├── scripts/            10 个脚本
│   ├── assets/             品牌资产 + Word 模板 + CSS
│   └── examples/
├── 天信日报/
├── 天信实务知识库/
└── 陈版主实务问答/
```

`README.md` 是安装器生成的清单，记了来源、安装时间、更新命令。**别在这里改技能**——下次同步会覆盖。

---

## 验证

```bash
python install.py --verify
```

四个对勾才算完。然后做一次真实触发：

> 用天信文档规范，把这篇 Markdown 出一份 Word

没反应的话看 [`05-常见问题.md`](05-常见问题.md) 的「装完不触发」一节。

---

## 只装其中几个

```bash
python install.py --global --only 天信日报
```

装了文档技能和实务知识库、不想装日报的，用这个。各技能互相独立，删掉任意一个不影响其余。

---

## 更新

```bash
cd tianxin-agents
git pull
python install.py --global --force
```

`--force` 会先删掉旧目录再复制，所以**你在安装目录里手改过的东西会丢**。要长期改，回仓库改。

看看更新了什么：

```bash
git log --oneline -10
git diff HEAD~1 --stat
```

---

## 卸载

```bash
# 删某一个
rm -rf ~/.workbuddy/skills/tianxin-docs

# 删全部四个
for d in 天信文档与报告 天信日报 天信实务知识库 陈版主实务问答; do
  rm -rf ~/.workbuddy/skills/"$d"
done
```

**不要 `rm -rf ~/.workbuddy/skills`**——那个目录里还有你自己装的别的技能。

---

## 多人共用的机器

全局安装的语义是「这台机器上的当前用户」。如果一台机器多个账号，各装各的，互不影响。

如果是同一账号下的多人协作（比如共用一台工位机），建议改用[方式三 · 项目级](04-项目级安装.md)：规范跟着项目走，不会因为某个人装了旧版而全员受影响。
