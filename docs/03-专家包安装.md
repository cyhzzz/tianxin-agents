# 方式二 · 专家包安装（WorkBuddy）

装成一个 WorkBuddy 专家：左侧「专家」里出现「天信办公专家」，点开就是它，仓库里的技能自动挂在下面。

---

## 专家和技能的区别

同一批能力，两种存在形式：

| | 单独装技能 | 装成专家 |
|---|---|---|
| 入口 | 没有入口，靠对话里说中触发词自动调起 | 左侧「专家」→ 我的专家 → 天信办公专家，点开即用 |
| 上下文 | 只有技能的 `description` | 专家人设 + 全部技能。它知道自己是在为一家县城事务所干活 |
| 换人用 | 谁在这台机器上都能触发 | 谁选中这个专家谁就用 |
| 适合 | 自己一个人用 | 想要一个固定入口，或者几个人各自选自己的专家 |

**专家不是「更高级的技能」**，是「技能 + 一层身份说明」。天信的人设写在 `专家/agents/tianxin-office-expert.md`：先判文书性质再排版、会计判断走能力卡、不编造准则条文、不替代 CPA 判断。这层说明让它在模糊场景下也不会跑偏。

---

## 安装

```bash
git clone https://github.com/cyhzzz/tianxin-agents.git
cd tianxin-agents
python install.py --expert
```

它会做四件事：

1. 在 `~/.workbuddy/plugins/marketplaces/my-experts/plugins/tianxin-office-expert/` 建专家目录
2. 写入 `plugin.json`（展示名、行业分类、三个标签、三个推荐问法）
3. 复制人设 `agents/tianxin-office-expert.md` 和头像 `avatars/`
4. 把 `plugin.json` 声明的技能目录复制进去，并注册到 `marketplace.json`

`marketplace.json` 那一步不能省——不注册，WorkBuddy 里根本看不到这个专家。

---

## 装完在哪找

打开 WorkBuddy → 左侧栏「**专家**」→ **我的专家** → 「天信办公专家」。

点开会看到三句推荐问法，第一条是默认引导：

> 把这份尽调稿按天信的规范出一份 Word，页眉页脚和三线表都要对。

**没看到专家**：重启 WorkBuddy 再进一次。还不行就检查 `~/.workbuddy/plugins/marketplaces/my-experts/.codebuddy-plugin/marketplace.json` 里有没有 `tianxin-office-expert` 这一条。

---

## 专家包里有什么

```
~/.workbuddy/plugins/marketplaces/my-experts/plugins/tianxin-office-expert/
├── .codebuddy-plugin/
│   └── plugin.json                  元数据：展示名、分类、标签、推荐问法
├── agents/
│   └── tianxin-office-expert.md     人设：这家所怎么干活
├── avatars/
│   └── tianxin-office-expert.png    头像（天信印章标，512×512）
└── skills/
    ├── 天信文档与报告/
    ├── 天信日报/
    ├── 天信实务知识库/
    └── 陈版主实务问答/
```

`plugin.json` 里的 `skills` 字段列出技能路径，WorkBuddy 启动这个专家时会把它们预加载进上下文。**加新技能时只改这一处**，安装器会照它复制并校验。

**别在这个目录里改东西**——`git pull` 后重装会覆盖。要改回仓库改。

---

## 只挂部分技能

```bash
python install.py --expert --only 天信文档与报告
```

装了之后专家目录里只有这一个技能。适合只想用文档能力、不想让日报和陈版主问答占上下文的情况。

补回其余技能：不带 `--only` 再跑一次。

---

## 更新

```bash
cd tianxin-agents
git pull
python install.py --expert --force
```

`--force` 会全量重装专家目录。不加 `--force` 是增量覆盖（技能目录会重建，人设和头像会覆盖，但不会删掉你自己加的文件）。

---

## 打包给别人

专家目录本身就能打包成一个 zip，对方解压到自己的专家目录即可，不需要跑脚本：

```bash
cd tianxin-agents
python -c "
import zipfile, os
root = os.path.expanduser('~/.workbuddy/plugins/marketplaces/my-experts/plugins')
src = os.path.join(root, 'tianxin-office-expert')
with zipfile.ZipFile('tianxin-office-expert.zip', 'w', zipfile.ZIP_DEFLATED) as z:
    for dp, _, fns in os.walk(src):
        for fn in fns:
            p = os.path.join(dp, fn)
            z.write(p, os.path.relpath(p, root))
print('done')
"
```

对方拿到 zip 后：解压到 `~/.workbuddy/plugins/marketplaces/my-experts/plugins/`，然后在 `marketplace.json` 的 `plugins` 数组里加一条：

```json
{
  "name": "tianxin-office-expert",
  "source": "./plugins/tianxin-office-expert",
  "description": "Tianxin CPA Office Expert",
  "version": "1.0.0"
}
```

重启 WorkBuddy。

## 手动安装（没有 Python 时）

```bash
# 1. 建目录
EXP=~/.workbuddy/plugins/marketplaces/my-experts/plugins/tianxin-office-expert
mkdir -p "$EXP/.codebuddy-plugin" "$EXP/agents" "$EXP/avatars" "$EXP/skills"

# 2. 拷元数据、人设、头像（源目录是「专家」，不是 expert）
cp 专家/plugin.json      "$EXP/.codebuddy-plugin/"
cp 专家/agents/*.md      "$EXP/agents/"
cp 专家/avatars/*.png    "$EXP/avatars/"

# 3. 拷技能。源目录名 ≠ 安装名，要用 SKILL.md 里的 name 作目标目录名
cp -r 公用/天信文档skill         "$EXP/skills/天信文档与报告"
cp -r 公用/天信实务知识库skill    "$EXP/skills/tianxin-shiwu-kb"
cp -r 公用/陈版主实务问答skill    "$EXP/skills/chenyiwei-bbs"
cp -r 审计/天信审计底稿           "$EXP/skills/天信审计底稿"
cp -r 税务/天信税务申报skill      "$EXP/skills/天信税务申报"
cp -r 运营/天信日报skill          "$EXP/skills/tianxin-daily-brief"
```

**目标目录名必须与 `专家/plugin.json` 里 `skills` 数组写的名字逐字一致**，否则专家能打开、技能一个也加载不了，而且不报错。

第四步注册必须手工编辑 `~/.workbuddy/plugins/marketplaces/my-experts/.codebuddy-plugin/marketplace.json`，在 `plugins` 数组里加上面那段 JSON。

---

## 卸载

```bash
rm -rf ~/.workbuddy/plugins/marketplaces/my-experts/plugins/tianxin-office-expert
```

再从 `marketplace.json` 的 `plugins` 数组里删掉那一条。不删那条，专家中心会显示一个打不开的空壳。

---

## 一个坑

专家包里的技能是**副本**，和全局 `~/.workbuddy/skills/` 下的同名技能互不干扰。如果两边都装了，改一边不影响另一边。

想只维护一份，就别同时用方式一和方式二——选一个。如果确实两边都要（比如既想全局用、又想有个专家入口），记得每次 `git pull` 后两条命令都跑一遍。
