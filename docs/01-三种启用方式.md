# 三种启用方式：怎么选

同一批技能，三种存在形式。差别不在功能，在**生效范围**和**更新成本**。

仓库里的技能分三层：**公用能力**（文档、实务知识库、陈版主问答）、**运营**（日报）、**业务线**（审计/税务/代理记账/企业咨询/评估造价，税务已建、其余四条待建）。三种方式装的内容略有差别，见下表「装几个」一行。

---

## 一句话决策

| 你的情况 | 选 |
|---|---|
| 平时固定用 WorkBuddy / Claude Code / Cursor 这类支持 skill 的工具 | **方式一 · 全局** |
| 想要一个固定入口：打开就是「天信办公专家」，公用能力全部带着 | **方式二 · 专家包** |
| 手上正在做一个客户项目，只想在那个目录里用 | **方式三 · 项目级** |
| 三种都想试 | 先装全局，不合适再删；专家包随时可加，两者不冲突 |

---

## 三种方式的真实差别

### 方式一 · 全局技能

技能文件复制到 `~/.workbuddy/skills/`（或对应平台的用户级目录）。之后**任何目录、任何对话**都能触发。

**好处**：装一次，全机可用。
**代价**：六个技能占 6 MB 左右，全部会话的上下文里都会有它们的 `description`（只有描述，不是全文，可以忽略不计）。
**什么时候不适用**：多人共用的机器；或者你只想让某个客户项目用到天信规范，不想污染其他项目的对话。

### 方式二 · 专家包

装成一个 WorkBuddy 专家：左侧「专家」里出现「天信办公专家」，仓库里的技能都挂在它下面，点开即用。

**好处**：一个固定入口，不用记哪个技能什么触发词；专家人设补上「这家所怎么干活」这层上下文，模糊场景也不跑偏。
**代价**：多占一份技能副本（约 3 MB）。而且只对 WorkBuddy 有效，换到别的 agent 用不了。

它和方式一的区别不在能力，在**入口**：方式一是「对话里说中触发词自动调起」，方式二是「明确选一个专家进去聊」。想分清自己该用哪个，问一句：你希望 AI 自己判断该用哪个技能，还是你每次主动选？前者方式一，后者方式二。

### 方式三 · 项目级

技能装进 `<项目>/.workbuddy/skills/`，只在该目录下的对话生效。

**好处**：项目自带配置，换电脑 `git clone` 项目就带着；不干扰其他项目。
**代价**：每个项目装一遍，更新要逐个 `git pull` + 重装。
**什么时候最合适**：给某个客户（比如一个长期服务的尽调项目）配一套专属规范，或者几个人协作，希望规范跟着仓库走。

---

## 组合用法

三种不冲突，可以叠加。常见的两种组合：

**全局 + 项目级**：全局装通用的（文档、实务知识库、陈版主问答），某个特殊项目再装一份定制的日报技能到项目里。项目级优先，同名技能以项目目录里的为准。

**专家 + 全局**：技能装全局保证任何对话都能触发，再装一个专家包做固定入口。两者共用同一份仓库，`git pull` 后两条安装命令都跑一遍即可。注意专家包里的技能是副本，不会自动跟着全局更新。

---

## 装错了怎么办

三种方式都是**纯文件**，删掉就恢复原状，不留痕迹：

```bash
# 方式一
rm -rf ~/.workbuddy/skills/天信文档与报告   # 只删一个
# 或删掉四个（不要整个 skills 目录，里面可能还有别的技能）

# 方式三
rm -rf /path/to/项目/.workbuddy/skills

# 方式二
rm -rf ~/.workbuddy/plugins/marketplaces/my-experts/plugins/tianxin-office-expert
# 再从同级的 marketplace.json 里删掉 tianxin-office-expert 那一条
```

删之前确认没有别的技能混在里面。`install.py --verify` 会列出现状。
