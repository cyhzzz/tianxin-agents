## 装完 AI 不理我

九成是 `SKILL.md` 的 `description` 没覆盖到用户的原话。

技能靠 `description` 里的文字匹配触发。如果用户说「帮我排个审计报告」而 description 里只写了「文书生产」，就对不上。

**检查**：

```bash
head -8 ~/.workbuddy/skills/天信文档与报告/SKILL.md
```

`description` 里应该有用户可能说的原话，不只是功能描述。天信文档技能的 description 现在包含：天信报告、天信Word、尽调报告、审计报告排版、专项报告、资产评估报告、公文格式、GB/T 9704、天信PPT、天信模板。

**补触发词**：在 description 里加用户的原话，别改工作流。

**还有一种可能**：技能名以 `_` 开头，或者 frontmatter 里 `name` 和目录名不一致。检查一下。

## 专家中心里没有「天信办公专家」

按顺序查三件事：

**一、目录在不在**

```bash
ls ~/.workbuddy/plugins/marketplaces/my-experts/plugins/tianxin-office-expert
```

应该看到 `.codebuddy-plugin/`、`agents/`、`avatars/`、`skills/` 四个子目录。

**二、注册了没有**

```bash
python -c "
import json, os
p = os.path.expanduser('~/.workbuddy/plugins/marketplaces/my-experts/.codebuddy-plugin/marketplace.json')
d = json.load(open(p, encoding='utf-8'))
print([x['name'] for x in d['plugins']])
"
```

列表里要有 `tianxin-office-expert`。没有就重跑 `python install.py --expert`。

**三、重启 WorkBuddy**

专家列表是启动时读的，装完不重启看不到。

## 中文技能名乱码

分两种：

**终端显示乱码，文件本身没问题。** Windows 的 cmd 默认 GBK。用 PowerShell 或 Git Bash，或者先跑 `chcp 65001`。

`install.py` 内部已按 UTF-8 读写，并在启动时尝试把 stdout 切到 UTF-8。如果还是乱码，是终端的问题不是文件的。

**文件名真的坏了。** 检查：

```bash
ls ~/.workbuddy/skills/ | cat -v
```

正常应该直接看到中文。如果显示成 `\344\270\255` 这种八进制，说明文件名在解压或复制时被错误编码，重新 `git clone` 一遍。

## 文档技能跑不起来

天信文档技能分两条链，依赖不同。

**Python 链**（Word 轨、预览、自检）：

```bash
pip install python-docx pymupdf pypdf Pillow numpy
```

| 缺什么 | 哪个脚本会报错 |
|---|---|
| `python-docx` | `md2docx.py`、`build_template.py`、`preview_docx.py`、`lint_docx.py` |
| `pymupdf` | `lint_pdf.py` |
| `pypdf` | `html2pdf.js` 合并封面与正文时（通过 Node 调 Python） |
| `Pillow` / `numpy` | 品牌资产处理脚本（一般用不到） |

**Node 链**（PDF 导出）：

```bash
npm install -g playwright
npx playwright install chromium
```

`html2pdf.js` 用 Playwright 的 Chromium 打印 PDF。没装浏览器内核会报「Executable doesn't exist」。

**先自检**：

```bash
cd ~/.workbuddy/skills/天信文档与报告
python scripts/md2docx.py --input examples/样例-尽调报告.md --output /tmp/t.docx
```

能出文件说明 Python 链通了。

## 陈版主问答报错

它依赖线上服务 `bbs.auditdog.cn`（公开可访，无需 token）。

**先测连通**：

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://bbs.auditdog.cn/api/search?q=收入确认
```

- 返回 200：服务正常，报错可能是查询词问题
- 超时或 5xx：服务暂时不可用，**技能应该如实报错，不要用训练数据编答案**
- 公司网络拦截：换网络或让 IT 放行

这个技能的设计前提是「宁可报错也不编」。如果发现它在服务不可用时还在给答案，那是 bug。

## 日报推送收不到

三个通道（5G 消息、微信服务号、邮件）都要先在 pushplus 绑定接收端，且需要 token。

**token 在哪**：`references/push-secrets.json`（本地，不入库）。没有这个文件就说明没配过。

**配法**：

```bash
cp references/push-config.example.md references/push-secrets.json
# 编辑它，把 PUSHPLUS_TOKEN 换成真实 token
```

云 agent 上跑的话，设环境变量 `PUSHPLUS_TOKEN`。

**邮件收不到**：检查接收邮箱是否绑定到 pushplus 账号。如果推给别人的邮箱，要先把对方加成好友。

## 更新之后行为变了

```bash
cd tianxin-skills && git log --oneline -10
```

看最近改了哪些。文档技能的规则改动都有对应记录，`天信文档skill/references/09-真实项目复盘.md` 里记了每次踩坑的来龙去脉。

**如果新版本破坏了你的用法**，两个选择：

```bash
# 一、退回上一个版本
git checkout HEAD~1

# 二、在本地改（不推荐，下次 git pull 会冲突）
```

改之前先想清楚：是规范真的错了，还是你的用法不在规范覆盖范围内。前者应该改仓库，后者应该在项目里加一个补充规则。

## 装了两份，行为不一致

全局和项目级都装了同名技能时，项目级优先。但专家包里的技能是**独立副本**，不和前两者联动。

症状：改了一处，另一处没变。

解法：想清楚用哪种，把另一种卸掉。两个都要的话，每次 `git pull` 后三条命令都跑：

```bash
python install.py --global --force
python install.py --expert --force
python install.py --project /path/to/项目 --force
```

## 权限错误

装全局时**不要用 sudo**。skills 目录在用户 home 下，不需要提权；用 sudo 装完文件归 root，之后普通用户改不了。

如果已经用 sudo 装过：

```bash
sudo chown -R $(whoami) ~/.workbuddy/skills
```

## 还想加功能

改仓库，别改安装目录。安装目录里的东西 `git pull` + 重装就冲掉了。

流程：

```bash
cd tianxin-skills
# 改技能目录里的内容
git add -A && git commit -m "..." && git push

# 重新装
python install.py --global --force
```
