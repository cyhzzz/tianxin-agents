# 01 弹性编排与接单判定

> 天信代账线的核心思想：**客户给的资料从来不齐**。不要跑死板流水线，按客户手里实际有什么，从对应环节切入。

## 一、接单四问（开工前必问）

1. **手里有什么**：原始票据（图片/PDF）／发票清单／凭证账簿／已有报表／只要复核？
2. **主体情况**：适用准则（企业会计准则 / 小企业会计准则）？纳税人类型（小规模 / 一般纳税人）？行业？
3. **要我们做什么**：全包代账／补一段断账／只出报表／只报税／只合规审查？
4. **对接与期限**：对接人是谁？申报截止日 / 报表交付日？

## 二、入口路由表

| 客户手里有 | 入口环节 | 走哪条 |
|---|---|---|
| 原始票据（图 / PDF） | 票据处理 → 凭证 | 03 → 04 |
| 发票清单 | 直接记账（凭证） | 04 |
| 凭证 / 账簿 | 报表 | 06 |
| 已有报表 | 申报 | 09 |
| 只要求合规审查 | 复核 / 预警 | 13 |

> 客户可能早就有账，只是换所或补一段。**不要强行从建账开始**。

## 三、资料缺口处理

- 缺原始票据：请客户补，不得凭口述做账（见 SKILL.md 纪律）。
- 跨期缺失：标注断点，先从有资料期切入，断点单独列「待补」区。
- 票据不齐但有清单：以清单建账，差异项标记，待票到后回填。

## 四、客户结构记录

每个代账客户建一份档案（落 `assets/接单判定表.md` 扩展），至少记：

- 行业、纳税人类型、适用准则
- 资料完整度（齐 / 部分 / 仅清单）
- 对接人、申报周期、特殊事项（如走逃供应商、异常凭证）

## 五、输出物

- 接单判定结论：从哪步进、缺什么、谁确认
- （如为新客）建账任务单转 02
