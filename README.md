# 天信 Agents

天台天信会计师事务所的业务线技能库。按所里实际的活分七类：公用能力三条、业务线四条已规划到五条、运营一条。**一个专家挂全部技能**，装好之后 AI 知道这家所怎么出报告、怎么查实务、怎么写日报、上哪儿找准则问答。

> **不想读文档？** 把这句话粘给任何能跑命令的 AI，它会替你装好：
>
> ```
> 克隆 https://github.com/cyhzzz/tianxin-agents 到本地，读 START-HERE.md，按里面的三选一让我挑一种装法装好，装完跑 --verify 验收。
> ```
>
> 更多说法（对方不能跑命令、已想好装哪种、只想先看看）见 [`一句话启用.md`](一句话启用.md)。

> **如果你是读到这个仓库的 AI**，不要急着解释这个仓库是什么。
> 先读 [`START-HERE.md`](START-HERE.md)，它会告诉你怎么判断环境、怎么让用户三选一、怎么落地。

## 一个专家，挂全部业务线

仓库里只有一个专家「**天信办公专家**」（`专家/`），它的 `plugin.json` 声明了所有技能。装好之后在 WorkBuddy 左侧「专家 → 我的专家」里点开它，七类能力都在。

**为什么不大卸八块做成五个专家**：所里 17 个人，业务是交叉的——做审计的也接代账，代账的遇到报表问题要查审计准则。拆成五个专家，用户每次得先想「我这个问题算哪条线」，想错了就调不到能力。一个专家靠技能触发词自动判断，反而更省事。

加新技能时，除了建目录，还要在 `专家/plugin.json` 的 `skills` 里加一行——不然后装出来的专家带不动它。

## 三种启用方式，选一个

| | 方式一 · 全局技能 | 方式二 · 专家包 | 方式三 · 项目级 |
|---|---|---|---|
| **适合** | 一个人用，所有项目都要 | 想要一个固定入口：打开就是「天信办公专家」 | 一个客户 / 一个项目专用 |
| **装到哪** | `~/.workbuddy/skills/` | `~/.workbuddy/plugins/marketplaces/my-experts/plugins/` | `<项目>/.workbuddy/skills/` |
| **装几个** | 仓库里全部技能 | 只装 `plugin.json` 声明的 | 仓库里全部技能 |
| **生效范围** | 这台机器上所有对话 | 被选为该专家的每一个会话 | 那个目录下的对话 |

**不确定选哪个**：想要固定入口、不想记触发词 → 方式二。想在任何对话里都能用 → 方式一。给某个客户单独配 → 方式三。

详细步骤见 [`docs/01-三种启用方式.md`](docs/01-三种启用方式.md)。

## 快速开始

需要 Python 3.8+。不需要 pip 装任何东西。

```bash
git clone https://github.com/cyhzzz/tianxin-agents.git
cd tianxin-agents

python install.py --list          # 看有哪些技能、装到哪
```

然后按你的选择跑其中一条：

```bash
python install.py --global                    # 方式一
python install.py --expert                    # 方式二
python install.py --project /path/to/项目      # 方式三
```

验证：

```bash
python install.py --verify
python install.py --verify --project /path/to/项目
```

它会逐个报告：目录在不在、`SKILL.md` 在不在、frontmatter 能不能解析、references / cards / 脚本齐不齐，顺带看一眼专家包装没装。

**Windows 用户**：路径用正斜杠或双反斜杠，例如 `--project D:/客户/某某尽调项目`。

## 装完之后能干什么

**场景一 · 出一份尽调报告的三个版本。** 26,000 字的 Markdown 尽调稿，要一份能签字的 Word、一份发得出去的 PDF、一份会上讲的网页。说一句「按天信文档规范出 Word / PDF / 长页」，四轨脚本跑完，机械自检拦住 schema 顺序错误、表头没重复、页眉错位、封面日期取成今天这些肉眼看不见的毛病。

**场景二 · 卡在一个会计判断上。** 「这家公司把政府补助记在其他收益，对不对？」实务知识库调 CAS16 那张卡，给出判断框架、天信场景、以及该问客户要什么材料。要准则原文就转给陈版主问答。

**场景三 · 每天早上七点要一份行业情报。** 天信日报抓审计行业热点和台州本地的审计选聘、代理记账采购公告，筛出与县城中小所相关的，推送到手机 5G 消息和邮箱。

## 仓库结构

这个仓库**同时是作者本机项目空间里的「天信本身」目录**。发出去的技能和内部分资产在同一个目录下，后者靠 `.gitignore` 排除——这样只有一份文件，不会出现两个副本要同步的问题。

```

├── README.md  START-HERE.md  一句话启用.md  LICENSE

├── docs/                         五份说明
├── 公用/                         跨业务线的三条
│   ├── 天信文档skill/             → 天信文档与报告
│   ├── 天信实务知识库skill/        → tianxin-shiwu-kb
│   └── 陈版主实务问答skill/        → chenyiwei-bbs
├── 审计/                         待建（见 README）
├── 税务/                         待建
├── 代理记账/                      待建
├── 企业咨询/                      待建
├── 评估造价/                      待建
├── 运营/
│   └── 天信日报skill/             → tianxin-daily-brief
└── 专家/                         一个专家，挂全部技能
    ├── plugin.json               声明挂哪些技能
    ├── agents/tianxin-office-expert.md
    └── avatars/tianxin-office-expert.png

不进仓库（.gitignore 排除，文件仍在本机）：
```

## 这套东西是怎么来的

不是照着通用模板写的。每一条规则背后都有一次具体的失误：

- 文档技能的「先判文书性质」来自一个事实：审计报告的段落顺序是准则规定的，拿咨询报告的思路去美化它，问题不在好看不好看，在合规不合规。
- 「`---` 不是分页符」来自一份 13 章的报告被切成 41 页、21 页只有小半内容。
- 「表头必须跨页重复」来自风险清单在续页只剩一行数据，读者不知道那行属于哪几列。
- 「封面日期不能取今天」来自 6 月编制的报告在 10 月排版，封面印着 10 月。

完整复盘在 `公用/天信文档skill/references/09-真实项目复盘.md`，九个问题逐个记了症状、根因、修法。**改这个仓库之前先读它**。

## 维护

仓库就是开发目录，改完直接提交：

```bash
cd 天信本身
git add -A && git commit -m "..." && git push
```

**没有第二份副本要同步**。装过的地方跟着更新：

```bash
python install.py --global --force
python install.py --expert --force
python install.py --project <目录> --force
```

**加一个新技能**要动三处：建目录写 `SKILL.md`、在对应业务线 README 里登记、在 `专家/plugin.json` 的 `skills` 加一行。

## 边界

**作为项目目录**：`天信本身/` 代表「事务所自己的事」——所内赋能、方法论沉淀、自身资产，**不对应某个付费客户**。以天信名义服务的企业客户放 `../企业咨询/`。

**作为技能仓库**：

- **不替代 CPA 判断**。技能给框架和格式，签字和结论由人负责。
- **不承诺合规**。审计报告要素是否齐全，最终以准则和所内质控为准。
- **陈版主问答依赖线上服务**（`bbs.auditdog.cn`）。服务不可用时技能会报错，不会编造答案。
- **没有真实材料不写业务线技能**。编出来的作业流程用一次就废。
- 仓库里的样例都是虚构企业。真实客户材料不入库。
