# 天信 Agents

天台天信会计师事务所的业务线技能库。按所里实际的活分三层：**公用能力**三条（文档出版、实务判断、准则检索）、**业务线**六条（审计、税务、代理记账、会计核算、评估造价、企业咨询，技能均已建，状态一律为**初稿**）、**运营**一条（日报）。**一个专家挂全部技能**，装好之后 AI 知道这家所怎么出报告、怎么编审计底稿、怎么算税报税、怎么做会计核算与资产评估、怎么给客户做管理咨询、怎么查实务、上哪儿找准则问答。

> **不想读文档？** 把这句话粘给任何能跑命令的 AI，它会替你装好：
>
> ```
> 克隆 https://github.com/cyhzzz/tianxin-agents 到本地，进仓库根目录读 START-HERE.md，按里面的默认方式把全部技能装到本机全局，装完跑 python install.py --verify 验收，最后告诉我另外两种装法分别在什么时候该换成。
> ```
>
> 更多说法（对方不能跑命令、已想好装哪种、只想先看看）见 [`一句话启用.md`](一句话启用.md)。

> **如果你是读到这个仓库的 AI**，不要急着解释这个仓库是什么。
> 先读 [`START-HERE.md`](START-HERE.md)，它会告诉你怎么判断环境、默认该装成哪种、怎么落地。

## 一个专家，挂全部业务线

仓库里只有一个专家「**天信办公专家**」（`专家/`），它的 `plugin.json` 声明了所有技能。装好之后在 WorkBuddy 左侧「专家 → 我的专家」里点开它，全部技能都在。

**为什么不大卸八块做成五个专家**：所里 17 个人，业务是交叉的——做审计的也接代账，代账的遇到报表问题要查审计准则。拆成五个专家，用户每次得先想「我这个问题算哪条线」，想错了就调不到能力。一个专家靠技能触发词自动判断，反而更省事。

加新技能时，除了建目录，还要在 `专家/plugin.json` 的 `skills` 里加一行——不然后装出来的专家带不动它。

## 三种启用方式：默认装全局

**不给参数就装全局**（方式一）——所有目录、所有对话都能用，覆盖绝大多数情况：

```bash
python install.py
```

另外两种按需换：

| | 方式一 · 全局技能 **(默认)** | 方式二 · 专家包 | 方式三 · 项目级 |
|---|---|---|---|
| **命令** | `python install.py` | `python install.py --expert` | `python install.py --project <目录>` |
| **什么时候换** | —— | 想要固定入口，打开就是「天信办公专家」 | 只想在某一个项目里用 |
| **装到哪** | `~/.workbuddy/skills/` | `~/.workbuddy/plugins/marketplaces/my-experts/plugins/` | `<项目>/.workbuddy/skills/` |
| **装几个** | 仓库里全部技能 | 只装 `plugin.json` 声明的 | 仓库里全部技能 |
| **生效范围** | 这台机器上所有对话 | 被选为该专家的每一个会话 | 那个目录下的对话 |
| **限制** | 无 | 只对 WorkBuddy 有效 | 每个项目装一遍 |

三种方式装的是同一批技能，差别只在生效范围。全局装完再装专家包也不冲突
（专家包里是副本，两者共用同一份仓库）。

详细步骤见 [`docs/01-三种启用方式.md`](docs/01-三种启用方式.md)。

## 快速开始

需要 Python 3.8+。不需要 pip 装任何东西。

```bash
git clone https://github.com/cyhzzz/tianxin-agents.git
cd tianxin-agents

python install.py --list          # 看有哪些技能、装到哪
```

然后这条就够了（默认装到本机全局）：

```bash
python install.py
```

要换成另外两种就加参数：

```bash
python install.py --expert                    # 装成 WorkBuddy 专家
python install.py --project /path/to/项目      # 只装进某个项目
```

验证：

```bash
python install.py --verify                            # 验收全局
python install.py --verify --project /path/to/项目     # 验收项目级
```

它会逐个报告：目录在不在、`SKILL.md` 在不在、frontmatter 能不能解析、references / cards / 脚本齐不齐，顺带看一眼专家包装没装。

**Windows 用户**：路径用正斜杠或双反斜杠，例如 `--project D:/客户/某某尽调项目`。

## 装完之后能干什么

**场景一 · 出一份尽调报告的三个版本。** 26,000 字的 Markdown 尽调稿，要一份能签字的 Word、一份发得出去的 PDF、一份会上讲的网页。说一句「按天信文档规范出 Word / PDF / 长页」，五轨脚本跑完，机械自检拦住 schema 顺序错误、表头没重复、页眉错位、封面日期取成今天这些肉眼看不见的毛病。

**场景二 · 卡在一个会计判断上。** 「这家公司把政府补助记在其他收益，对不对？」实务知识库调 CAS16 那张卡，给出判断框架、天信场景、以及该问客户要什么材料。要准则原文就转给陈版主问答。

**场景三 · 每天早上七点要一份行业情报。** 天信日报抓审计行业热点和台州本地的审计选聘、代理记账采购公告，筛出与县城中小所相关的，推送到手机 5G 消息和邮箱。

## 这套东西是怎么来的

不是照着通用模板写的。每一条规则背后都有一次具体的失误：

- 文档技能的「先判文书性质」来自一个事实：审计报告的段落顺序是准则规定的，拿咨询报告的思路去美化它，问题不在好看不好看，在合规不合规。
- 「`---` 不是分页符」来自一份 13 章的报告被切成 41 页、21 页只有小半内容。
- 「表头必须跨页重复」来自风险清单在续页只剩一行数据，读者不知道那行属于哪几列。
- 「封面日期不能取今天」来自 6 月编制的报告在 10 月排版，封面印着 10 月。
- 「上游原文原样收、不做融合蒸馏」来自代账线：上游 7 个能力模块 2221 行，被"读懂了再写一篇中文"压成 498 行，审批矩阵、复核清单、常见错误自查全没了。**理解的产物可以写，原文不能扔**——现在原文在技能根的 `上游/`，适配层在 `references/`，两层并列。

完整复盘在 `公用/天信文档skill/references/09-真实项目复盘.md`，九个问题逐个记了症状、根因、修法。**改这个仓库之前先读它**。

## 维护

仓库就是开发目录，改完直接提交：

```bash
cd 天信本身
git add -A && git commit -m "..." && git push
```

**没有第二份副本要同步**。装过的地方跟着更新：

```bash
python install.py --global --force
python install.py --expert --force
python install.py --project <目录> --force
```

**加一个新技能**要动三处：建目录写 `SKILL.md`、在对应业务线 README 里登记、在 `专家/plugin.json` 的 `skills` 加一行。

**要并入外部专家的能力**，别"读懂再重写一遍"——原文原样收到技能根的 `上游/`，天信怎么用另写一层。规矩见 `AGENTS.md` §3.1，样本看 `代理记账/天信代账作业skill/上游/`。

改完跑一遍 `python check.py`——它查链接断没断、专家包一不一致、文档里的技能数量对不对。

## 技能不完美，欢迎改

审计、税务、代理记账三条线都是按**通用实务**编的，天信自己的底稿格式、作业流程、
当地税务口径还没换进去。用的人一定会发现问题。

用着发现错，**优先直接改文件再回传**：

```bash
# 改了 ~/.workbuddy/skills/tianxin-bookkeeping/ 里的文件之后
python contribute.py --from-installed ~/.workbuddy/skills/tianxin-bookkeeping
```

它比对副本与仓库、建分支、提交、开 PR。不需要会 git。
只发现问题没改文件，就用 `python contribute.py --proposal <提案文件>`。

每个 `SKILL.md` 末尾都写了这个流程——**装出去的是副本，AI 读不到本仓库**，
所以触发器必须跟着副本走。详见 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

## 边界

**作为项目目录**：`天信本身/` 代表「事务所自己的事」——所内赋能、方法论沉淀、自身资产，**不对应某个付费客户**。以天信名义服务的企业客户放 `../企业咨询/`。

**作为技能仓库**：

- **不替代 CPA 判断**。技能给框架和格式，签字和结论由人负责。
- **不承诺合规**。审计报告要素是否齐全，最终以准则和所内质控为准。
- **陈版主问答依赖线上服务**（`bbs.auditdog.cn`）。服务不可用时技能会报错，不会编造答案。
- **没有真实材料不写业务线技能**。编出来的作业流程用一次就废。
- 仓库里的样例都是虚构企业。真实客户材料不入库。
