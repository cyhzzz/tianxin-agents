# 天信办公专家 · Tianxin Office Skills

天台天信会计师事务所的四个 AI 技能包。装好之后，AI 知道这家所怎么出报告、怎么查实务、怎么写日报、上哪儿找准则问答。

> **不想读文档？** 把这句话粘给任何能跑命令的 AI，它会替你装好：
>
> ```
> 克隆 https://github.com/cyhzzz/tianxin-skills 到本地，读 START-HERE.md，按里面的三选一让我挑一种装法装好，装完跑 --verify 验收。
> ```
>
> 更多说法（对方不能跑命令、已想好装哪种、只想先看看）见 [`一句话启用.md`](一句话启用.md)。

> **如果你是读到这个仓库的 AI**，不要急着解释这个仓库是什么。
> 先读 [`START-HERE.md`](START-HERE.md)，它会告诉你怎么判断环境、怎么让用户三选一、怎么落地。

## 四个技能

| 技能 | frontmatter name | 目录 | 干什么 |
|---|---|---|---|
| **天信文档与报告** | `天信文档与报告` | `天信文档skill/` | 判文书性质 → 选轨道 → 出 Word / A4 PDF / 网页长页 / 演示 deck。带天信页眉页脚、三线表、事实/行业/推演三级标记、待复核水印 |
| **天信日报** | `tianxin-daily-brief` | `天信日报skill/` | 抓审计行业热点 + 台州本地财务咨询/代理记账/审计选聘商机，筛出与县城中小所相关的条目 |
| **天信实务知识库** | `tianxin-shiwu-kb` | `天信实务知识库skill/` | 12 张实务能力卡：CAS14 收入、小企业准则适用、审计四程序、监管处罚前车之鉴、税务实务、政府补助、资产减值、差错更正、年报审计 SOP |
| **陈版主实务问答** | `chenyiwei-bbs` | `陈版主实务问答skill/` | 检索陈奕蔚（陈版主）在会计视野论坛的实务答疑与准则原文，直连公开 REST API，无需 token |

目录名带 `skill` 后缀是作者本机的命名习惯；安装器按 `SKILL.md` 里的 `name` 决定安装后的目录名，两者不一致是正常的。

四个技能互相独立，可以只装一个。但**文档 + 实务知识库**是一对：写报告时遇到会计判断，前者出格式，后者出结论。

## 三种启用方式，选一个

| | 方式一 · 全局技能 | 方式二 · 专家包 | 方式三 · 项目级 |
|---|---|---|---|
| **适合** | 一个人用，所有项目都要 | 想要一个固定入口：打开就是「天信办公专家」，四个技能自动带着 | 一个客户 / 一个项目专用 |
| **装到哪** | `~/.workbuddy/skills/`（或对应 agent 的用户级目录） | WorkBuddy 专家目录 `~/.workbuddy/plugins/marketplaces/my-experts/plugins/` | `<项目>/.workbuddy/skills/` |
| **在 WorkBuddy 里长什么样** | 对话中自动触发，看不见摸不着 | 左侧「专家」→ 我的专家 → **天信办公专家**，点开即用 | 在那个目录下对话时自动触发 |
| **生效范围** | 这台机器上所有对话 | 被选为该专家的每一个会话 | 那个目录下的对话 |
| **代价** | 全局多占几 MB | 多占一份技能副本（约 3 MB） | 每个项目装一遍 |

**不确定选哪个**：

- 想要「一个入口，进去就聊」，不想记技能触发词 → **方式二**
- 想在所有工具里都能用（含非 WorkBuddy 的 agent） → **方式一**
- 给某个客户单独配一套，或者希望规范跟着项目仓库走 → **方式三**

方式二的本质是**把四个技能打包成一个带人设的专家**：专家说明写清「天信怎么做文书、怎么判会计处理」，技能提供具体执行能力。它比单纯装 skill 多一层上下文——AI 知道自己是在为一家县城事务所干活，而不是泛泛地排版。

详细步骤见 [`docs/01-三种启用方式.md`](docs/01-三种启用方式.md)。

## 快速开始

需要 Python 3.8+。不需要 pip 装任何东西。

```bash
git clone https://github.com/cyhzzz/tianxin-skills.git
cd tianxin-skills

python install.py --list          # 先看有哪些技能、装到哪
```

然后按你的选择跑其中一条：

```bash
# 方式一：装成本机所有对话可用
python install.py --global

# 方式二：装成 WorkBuddy 专家（一个专家挂四个技能）
python install.py --expert

# 方式三：装进某个项目目录
python install.py --project /path/to/你的项目
```

装完验证：

```bash
python install.py --verify
python install.py --verify --project /path/to/你的项目    # 项目级的验收
```

它会逐个报告：目录在不在、`SKILL.md` 在不在、frontmatter 能不能解析、references / cards / 脚本齐不齐，顺带看一眼专家包装没装。

**Windows 用户**：路径用正斜杠或双反斜杠，例如 `--project D:/客户/某某尽调项目`。

## 装完之后能干什么

举三个真实场景，看你能不能对上：

**场景一 · 出一份尽调报告的三个版本。** 手上有 26,000 字的 Markdown 尽调稿，要同时给客户一份能签字的 Word、一份发得出去的 PDF、一份能在会上讲的网页。说一句「按天信文档规范出 Word / PDF / 长页」，四轨脚本会跑完，机械自检会拦住 schema 顺序错误、表头没重复、页眉错位、封面日期取成今天这些肉眼看不见的毛病。

**场景二 · 写报告时卡在一个会计判断上。** 「这家公司把政府补助记在其他收益，对不对？」实务知识库会调 CAS16 那张卡，给出判断框架、天信场景、以及该问客户要什么材料。要准则原文就转给陈版主问答。

**场景三 · 每天早上七点要一份行业情报。** 天信日报抓审计行业热点和台州本地的审计选聘、代理记账采购公告，筛出与县城中小所相关的，推送到手机 5G 消息和邮箱。定时任务触发即可。

## 仓库结构

这个仓库**同时是作者本机项目空间里的「天信本身」目录**。发出去的技能和内部资产在同一个目录下，后者靠 `.gitignore` 排除，不是物理分开的——这样只有一份文件，不会出现两个副本要同步的问题。

```

├── README.md                     你正在读的
├── 一句话启用.md                 可直接粘给 AI 的 prompt
├── START-HERE.md                 给 AI 的执行说明书（三选一的落地步骤）
├── install.py                    安装器：--global / --project / --expert / --verify
├── LICENSE
├── docs/
│   ├── 01-三种启用方式.md         决策树与对比
│   ├── 02-全局安装.md
│   ├── 03-专家包安装.md           WorkBuddy 专家：一个专家挂四个技能
│   ├── 04-项目级安装.md
│   └── 05-常见问题.md
├── expert/                       方式二的产物：WorkBuddy 专家包
│   ├── plugin.json               专家元数据（展示名、分类、标签、推荐问法）
│   ├── agents/
│   │   └── tianxin-office-expert.md   专家人设与工作流
│   └── avatars/
│       └── tianxin-office-expert.png  头像（天信印章标）
├── 天信文档skill/                → 安装后叫「天信文档与报告」
├── 天信日报skill/                → 「tianxin-daily-brief」
├── 天信实务知识库skill/           → 「tianxin-shiwu-kb」
└── 陈版主实务问答skill/           → 「chenyiwei-bbs」

不进仓库（.gitignore 排除，文件仍在本机）：
├── 天信宣传片/                   92 MB，成片与渲染工程
├── tianxin-cpa-website-gh-pages/ 官网源码，有自己的仓库（tianxin-cpa.cn）
```

## 这套东西是怎么来的

不是照着通用模板写的。每一条规则背后都有一次具体的失误：

- 文档技能的「先判文书性质」来自一个事实：审计报告的段落顺序是准则规定的，拿咨询报告的思路去美化它，问题不在好看不好看，在合规不合规。
- 「`---` 不是分页符」来自一份 13 章的报告被切成 41 页、21 页只有小半内容。
- 「表头必须跨页重复」来自风险清单在续页只剩一行数据，读者不知道那行属于哪几列。
- 「封面日期不能取今天」来自 6 月编制的报告在 10 月排版，封面印着 10 月。

完整复盘在 `天信文档skill/references/09-真实项目复盘.md`，九个问题逐个记了症状、根因、修法。**改这个仓库之前先读它**，能省掉重踩一遍的时间。

## 维护

仓库就是开发目录，改完直接提交：

```bash
cd 天信本身
# 改技能内容
git add -A && git commit -m "..." && git push
```

**没有第二份副本要同步**——这是有意为之。不要为了「看起来整齐」再把技能复制到另一个文件夹，两边一分叉，就再也说不清哪份是对的。

装过的地方要跟着更新：

```bash
python install.py --global --force             # 方式一
python install.py --expert --force             # 方式二
python install.py --project <目录> --force      # 方式三
```

## 边界

**作为项目目录**：`天信本身/` 代表「事务所自己的事」——所内赋能、方法论沉淀、自身资产，**不对应某个付费客户**。以天信名义服务的企业客户放 `../企业咨询/`。往这里加东西时先判断一句：给所里自己用的放这里，给客户做的放那边。

**作为技能仓库**：

- **不替代 CPA 判断**。技能给框架和格式，签字和结论由人负责。
- **不承诺合规**。审计报告要素是否齐全，最终以准则和所内质控为准。
- **陈版主问答依赖线上服务**（`bbs.auditdog.cn`）。服务不可用时技能会报错，不会编造答案。
- 仓库里的样例都是虚构企业。真实客户材料不入库。
