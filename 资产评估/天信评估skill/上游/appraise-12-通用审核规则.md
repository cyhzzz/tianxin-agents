# 通用审核规则（文档级 + 交叉稽核 + 意见格式）

> 本文件摘录自《评估报告审核》通用基础层（G0）与交叉稽核、意见输出规范，**仅保留通用规则**（任何业务类型、任何评估报告都适用的部分），资产/专项层规则不在此列。
> 配合 `review-checklist.md`（执业维度三级负面清单）共同使用：本文件解决"文档级 / 元级"问题（骨架、标识、日期、依据、对象范围、特别事项、勾稽、格式），`review-checklist.md` 解决"执业维度"问题（方法、参数、预测、披露）。二者合并去重后执行。
> 另：当配合本机《评估报告审核》技能（含 G0 通用基础层、G1–G5 类型层、S1–S14 专项层与勾稽脚本）协同审报告时，本文件的 G0 通用层与交叉稽核方法以该技能输出为准，本文件仅作离线兜底；分工详见知识库 SKILL.md 第五节。**该技能近期已优化，本文件第三节"审核意见输出格式"已严格对齐其 `opinion_format_reference.md`，冲突时以该技能为准。**

## 〇、严重程度映射

本文件沿用来源的严重度标签，与 `review-checklist.md` 三级体系对应如下（注：三级仅作问题内部归类；审核技能批注用语为档位【SSS】/【SS】/【S】，两者对应但不混用，详见本节二·5 与第三节）：

| 来源标签 | 对应三级 | 处置 |
|---|---|---|
| 严重错误 | 重大缺陷 | 必须修改，影响结论有效性 |
| 普通错误 | 一般问题 | 建议修改，影响规范性与可复核性 |
| 基础信息错误 | 一般问题 | 属信息正确性与规范性，须修正 |

## 一、通用文档级审核清单（G0 · 34 条）

### A. 报告构成与骨架
- **G0-A1 报告六部分不齐【严重】**：核对标题及文号、目录、声明、摘要、正文、附件六部分是否齐备，缺一即记缺失项与应补位置。
- **G0-A2 摘要要素缺项【严重】**：摘要须同时载明评估目的、评估对象与范围、价值类型、评估基准日、评估方法、评估结论、特别事项提示，逐项核对缺项列名。
- **G0-A3 摘要与正文不一致【严重】**：将摘要的目的、对象范围、价值类型、基准日、方法、结论、有效期逐项与正文比对，不一致处**以正文为准**并记录差异双方取值。
- **G0-A4 声明内容不完整【一般】**：声明须含遵循法律法规与准则、独立客观公正、使用限制与免责表述，缺段即记。
- **G0-A5 附件清单与实际附件不符【一般】**：目录附件清单逐项与实际附件比对，双向记录（列了没有、有未列入）。
- **G0-A6 分册信息缺漏【一般】**：多册装订须标注册数与册序，封面与扉页标注一致。

### B. 基础标识与日期
- **G0-B1 报告文号缺失、占位或前后不一【一般】**：封面、摘要、正文落款三处文号逐字比对；出现星号、空格等占位符按缺失处理。
- **G0-B2 评估基准日全文不一致【严重】**：从摘要、正文、评估说明、明细表表头、底稿表头提取基准日，统一解析为年月日后比对，逐处记录差异（封面通常不载基准日，若载出则记"位置异常"但不纳入全文比对）。
- **G0-B3 报告日早于评估基准日【严重】**：报告日早于基准日即记录，注明两者取值。
- **G0-B4 有效期声明缺失或超期【一般】**：核对是否载明使用有效期及起算日；声明超过一年的记录并提示。
- **G0-B5 机构与人员签章不合规【严重】**：机构印章、法定代表人或合伙人签章、至少两名资产评估师签名须齐备，缺任一项即记。

### C. 评估依据
- **G0-C1 依据五类不齐【一般】**：按经济行为依据、法律法规依据、评估准则依据、权属依据、取价依据五类核对，缺类列名。
- **G0-C2 引用已废止或尚未施行的文件【严重】**：以**评估基准日**为时点判定每条依据效力；基准日已废止、或基准日尚未施行的逐条记录并给替代文件线索（检索不到写【未检索到】）。
- **G0-C3 取价依据笼统兜底【一般】**：关键参数的取价依据须写明来源与时间，不能只写"市场询价""公开资料"等无定位表述。
- **G0-C4 未使用的参数列入取价依据【一般】**：比对取价依据清单与测算实际使用参数，列入但未使用的逐项剔除提示。

### D. 评估对象、范围与权属
- **G0-D1 评估目的表述与经济行为不匹配【严重】**：评估目的表述与经济行为文件（决议、批复、协议）比对，口径不一致即记。
- **G0-D2 评估范围与申报范围不一致【严重】**：正文评估范围与企业申报明细表范围比对，表外资产、表内未申报资产分别核查是否说明。
- **G0-D3 权属瑕疵未披露【严重】**：是否已披露权属资料不完整、存在瑕疵的情形，并在特别事项重点提示使用人关注。
- **G0-D4 抵押质押查封冻结未说明【严重】**：核查对象是否存在抵押、质押、查封、冻结、出资瑕疵，已存在而未披露的逐项记。

### E. 特别事项与期后事项
- **G0-E1 特别事项类别覆盖不全【一般】**：按七类逐类核对——权属资料瑕疵、委托人未提供的关键资料、未决事项与法律纠纷、利用专家工作、重大期后事项、程序受限及弥补措施、其他需说明事项。
- **G0-E2 期后事项与报告日区间不闭合【一般】**：核对期后事项披露时间区间是否覆盖至报告日；未覆盖的记区间端点。
- **G0-E3 声明与披露事实冲突【一般】**：承诺函、各方声明内容与报告披露事实比对，矛盾处双向记录。

### F. 结论与披露
- **G0-F1 评估结论未同时列示大小写金额【一般】**：核对结论是否同时列示阿拉伯数字与大写金额，二者是否一致。
- **G0-F2 多方法结论差异未作说明【一般】**：采用两种以上方法的，核对是否说明差异原因及最终取值理由；简单算术平均而无说明的予以记录。
- **G0-F3 使用限制说明缺失【一般】**：核对是否载明使用限制，含使用人范围、用途限制、有效期限制，缺项列名。

### G. 底稿与表格
- **G0-G1 空白模板科目未过滤【一般】**：无实质业务数据的模板科目表一律忽略，其公式报错、残留参数、格式问题不得作为问题输出（判定标准见第三节）。
- **G0-G2 含实质数据的隐藏表被跳过【严重】**：凡含本项目实际测算、明细、中间计算数据的表，无论是否隐藏均须纳入审核；被跳过的逐一纳入。
- **G0-G3 索引标记与实际数据冲突【一般】**：索引表标不适用但含实质数据，或标适用但无数据的，逐条记录冲突双方。
- **G0-G4 逐级汇总链路断裂【严重】**：明细表 → 分类汇总表 → 总汇总表逐级核对，任一级对不上即记录两端取值与差异（差异 ≤ 0.01 不记）。
- **G0-G5 明细表与测算表序号不连续【一般】**：表格序号列逐行核对是否连续递增；跳号、重号、回退、缺号的逐处记录所在表与行号；按类别分组重编须表内说明规则，未说明的记。

### H. 文字与格式
- **G0-H1 金额单位不统一或换算错误【一般】**：全文金额单位标注是否一致，万元与元混用处换算后核对，小数位与千分位是否规范。
- **G0-H2 同一主体称谓前后不一【一般】**：委托人、被评估单位、产权持有人等主体在报告与说明中的称谓是否统一，简称与全称混用的记。
- **G0-H3 错别字与术语不规范【一般】**：扫描重复词、重复标点、混用异形词、专业术语误用、编号跳号、交叉引用章节号错误。
- **G0-H4 「本公司」指代对象错误【一般】**：报告与说明中的"本公司/我公司"一律指**评估机构**，不得指代被评估单位、产权持有单位或委托人；凡误用逐处记录并建议改为主体名称或规范简称；同一主体全文称谓须一致，不得混用"本公司/该公司/企业"。此错会误导责任主体判断，凡出现即改。

## 二、交叉稽核通用规则

交叉稽核回答一个问题：**同一项信息在不同位置是否一致**。它不依赖专业判断，取到值即可比对。

### 1. 容差（硬约束）
- 分项金额与汇总金额的差异，绝对值 **≤ 0.01 元** 视为一致，不输出、不提示；超过才作为差异输出，并写明两取值、差异金额、差异率与位置。
- 比率按小数后比较，容差 0.0001；日期统一解析为 YYYY-MM-DD 后比较，容差 0。
- 金额统一换算到"元"用 Decimal 比较。

### 2. 四类勾稽
- **同值勾稽**：同一指标在报告、评估说明、评估明细表、测算底稿各处取值必须相等；任一位置取不到值，记入"未检索到"交人工确认——不猜测、不跳过、不用其他位置数值填充。
- **算术勾稽**：行内增减值 = 评估值 − 账面值；增值率 = 增减值 ÷ 账面值 × 100%（账面为 0 时跳过）；合计明细 = 上级汇总；平衡 资产总计 = 负债总计 + 净资产；分级 流动+非流动 = 资产总计、流动+非流动负债 = 负债总计。
- **链路勾稽**：账面值（审计前）→ 账面值（审计后）→ 评估值，三段数值链完整可追溯；明细表 → 分类汇总表 → 总汇总表逐级相等；Excel 底稿 明细 sheet → 汇总 sheet → 主表。
- **口径勾稽（唯一需模型参与）**：文字描述的公式逻辑 vs 底稿单元格实际公式，重点查中间项是否遗漏（汇率、调整系数、折现期）；披露的评估方法 vs 实际存在的测算表（声明用某法但无对应表、或反之，记冲突）；索引表"适用与否"标记 vs 该 sheet 实际是否有实质数据。

### 3. 空白模板科目的处置（避免无效意见）
对没有实际数据信息的模板科目，**一律忽略，不产生任何审核意见**。三条件同时满足才判为空白模板（脚本自动执行）：
1. 公式单元格数 = 0；
2. 实质业务数据单元格数 < 8；
3. 无跨工作簿外部引用。
处置：判为空白的 sheet，其公式报错、残留参数、格式问题全部不输出；**被隐藏但含本项目实际测算/明细/中间计算数据的 sheet，无论是否隐藏，纳入完整审核**；只含少量说明文字（如 sheet 名称标签）仍判空白，不因"有一个标题"就纳入。原则：**宁可少提，不可为凑数把模板空科目写成问题**。

### 4. 通用勾稽对矩阵

| 编号 | 勾稽对 | 校验内容 |
| :-- | :-- | :-- |
| X01 | 报告正文 ↔ 评估说明 | 基准日、结论、方法、关键参数、假设、特别事项 |
| X02 | 报告正文 ↔ 汇总表 | 资产总计、负债总计、净资产、评估结论 |
| X03 | 总汇总表 ↔ 分类汇总表 | 各级合计行 |
| X04 | 分类汇总表 ↔ 明细表 | 各科目合计 |
| X05 | 评估明细表 ↔ Excel 底稿 | 同科目数值 |
| X06 | 评估说明 ↔ Excel 底稿 | 折现率、增长率、收入等参数 |
| X07 | 文字公式描述 ↔ 底稿实际公式 | 中间项完整性 |
| X08 | 摘要 ↔ 正文 | 结论、有效期、使用限制 |
| X09 | 索引表 ↔ 实际 sheet | "适用与否"标记与实际数据是否冲突 |
| X10 | 表内行 ↔ 表内合计 | 算术自洽 |
| X11 | 审计前 → 审计后 → 评估值 | 链路可追溯 |
| X12 | 封面 ↔ 落款 ↔ 正文 | 报告日、机构名、文号 |

> 股权类（企业价值）项目另有母公司↔子公司长投、内部往来抵消、合并层次等专项勾稽，不在本通用清单内。

### 5. 输出与定档
每个指标产出：各位置取值原文、归一化值、单位、位置（页码/表号/单元格）、是否一致、差异金额、差异率。
定档规则：
- 差异率 > 1%（或准则必备项缺失、依据在基准日已失效）→ **【SSS】严重**；
- 存在差异但 ≤ 1% → **【SS】一般**；
- 一致 → 不输出（仅记档）。
> 差异率是"上浮"规则：只会抬到 SSS，不会把一般/严重降下来。
> **档位只进批注、不进意见**：【SSS】/【SS】/【S】仅写在报告与说明的批注里；汇总《审核意见》不出现档位字样（与《评估报告审核》技能一致）。

## 三、审核意见输出格式（通用，离线版，严格对齐《评估报告审核》技能 `opinion_format_reference.md`）

> 本专家**离线**产出《审核意见》时按本节结构；**若已加载《评估报告审核》技能，其 `opinion_build.py` 生成的 docx 为权威交付物，本节仅作阅读与人工起草参照，不得与技能输出冲突。**
> 所有条目仅描述"哪里、什么问题"，整改/核实要求放报告批注。

### 1. 总体结构（严格对齐使用者给定的三份初审意见范本：单一主体股权 / 多主体公司 / 单项资产）

> **版式基准（强制）**：最终汇总《审核意见》严格按使用者给定的三份初审意见范本（随包附带于 `templates/opinion-style-examples/`，为样式参考样例，含样例项目数据，正式出具时由实际项目替换；与《评估报告审核》技能 `opinion_format_reference.md` 同源于使用者参考样式，冲突时**以这三份范本为准**）的版式生成；本专家离线起草或成稿校订亦以此三份范本为唯一基准。

```
标题区（各自成行；项目名可按语句换行，不强行合并单行）：
  ××公司拟[经济行为]涉及的××[价值类型]评估项目
  审核意见
  ××评报字[2026]第××号

评估报告
评估说明
  （▼ 多主体 / 多册：按主体短横连接、不编号，每主体单独成二级标题）
  评估说明-母公司
  涉及报告问题对照调整。
  评估说明-SGD公司
  涉及母公司问题对照调整。
  评估说明-HDH公司
  （▲ 单主体：不设二级标题，问题直接列在「评估说明」下）
评估明细表及测算表
  （▼ 多主体：按「方法 + 主体」短横连接、不编号，每主体单独成二级标题）
  资产基础法评估明细表及测算表-母公司
  房屋建筑物：①…②…
  资产基础法评估明细表及测算表-SGD公司
  市场法评估明细表-母公司
  （▼ 单主体多方法：按方法「（一）（二）」编号、叠写方法全称）
  （一）收益法评估明细表
  （二）资产基础法评估明细表及测算表
  （三）市场法评估明细表
  （▲ 单主体单方法：不设二级标题，问题直接列在「评估明细表及测算表」下）

审核人：
日期：2026年  月   日

答复人：
日期：2026年  月   日
```

结构硬规则：

- **一级章节不编序号**：直接写「评估报告」「评估说明」「评估明细表及测算表」，不带「一、二、三、」。
- **条目不编连续阿拉伯数字**：全篇无「1、2、3、」连续编号；条首只写 `P页码` 或 `科目`。
- **标题区分行**：项目名（可多行换行）、「审核意见」、「报告文号」各自成行，不合并成单行。
- **多册 / 多主体逐一审核（硬要求）**：
  - 项目涉及**多份评估说明、多套明细表 / 测算表**时，每一册、每一被评估主体都必须**单独成二级标题逐一审核**，不混排、不遗漏；无发现的册 / 主体也要列出并写「已审核，未发现需提示的问题。」，让读者看得出确实审过。
  - **多主体 / 多册 → 二级标题按主体短横连接、不编号**：`评估说明-母公司`、`评估说明-SGD公司`、`资产基础法评估明细表及测算表-母公司`、`市场法评估明细表-母公司`（参照多主体范本「北京热火股份有限公司」）。
  - **单主体多方法 → 二级标题按方法「（一）（二）」编号、叠写方法全称**：`（一）收益法评估明细表`、`（二）资产基础法评估明细表及测算表`、`（三）市场法评估明细表`；只采用一种方法时不插二级标题（参照单一主体范本「西安金融有限公司」）。
  - **单主体单方法 → 不插二级标题**，问题直接列在父章节下（参照单项资产范本「中国神州科技有限公司」）。
  - **跨主体不合并**：不同被投资单位的问题一律分列在各自主体标题下；同一主体下涉及的科目也必须逐条分列（即便文字相同也不写成「应收账款、其他应收款：…」这种并列一条），便于逐户答复。
- **说明册引导语**：多主体时，每主体说明第一行固定「涉及报告问题对照调整。」（母公司首册）或「涉及母公司问题对照调整。」（后续主体），与范本一致。
- **落款含答复人**：末尾固定「审核人： / 日期：」与「答复人： / 日期：」四行（与三份范本一致）。

### 2. 行文体例

- **docx 类发现（报告/说明）**：格式 `P{页码}，“{原文}”{简练描述}。`
  - 页码为真实页码（借 Word 引擎反查），无页码回退为结构定位串（如 `评估说明/表2/第2行`）或段落号，**绝不编造页码**。
  - 描述只说清「哪里、什么问题」；整改/核实要求放报告批注，意见里不展开。
  - 引述原文用全角弯引号“”。
  - 判断类事项（`tone=question`）按句式定标点：本身是疑问句以「？」结尾；「请核实/请补充/建议…」等祈使建议句式以「。」结尾，不硬加问号。
- **xlsx 类发现（明细表/测算表）**：格式 `{科目}：{问题}。`；同一科目多处问题合并为一条，用①②③分述。
  - 表格无页码概念，条首直接用**科目名称**引领，不写 P 页码。
  - 一个科目一条：多处问题不逐条罗列；不同科目不并列成一条；跨主体的问题分列在各自主体小标题下。
  - 科目顺序按资产申报表/评估明细表的表页顺序，不按科目名字典序重排。

### 3. 语气与表述

- **明显错误用肯定句**（税率适用错误、前后矛盾、缺必备章节/要素、公式勾稽不平、序号重号/跳号、笔误）。
- **判断事项用疑问句**（参数取值偏高/偏低、选取依据是否充分、方法适用性、披露是否充分、预测逻辑是否合理）。
- 判定口诀：能直接下结论的（错即对、对即错）用肯定；需要评估师解释或判断的用提问。

### 4. 脱敏红线（强制）

- 内置模板、参考样例、脚本常量中**不得出现**任何具体项目名称、被评估单位、报告文号、金额、人名、联系方式、证照编号。
- 条目描述只抽抽象审核关注要点（「XX 数据不一致」「XX 重复」），不得点名具体项目。
- 真实项目信息由审核时从待审文件抽取，绝不预置。

### 5. 档位不进意见（与审核技能一致）

- 档位【SSS】/【SS】/【S】**只写在报告与说明的批注里**，汇总《审核意见》不出现档位字样——意见是交给项目组答复的正式文件，只写问题、位置与依据。
- 本包三级（重大缺陷 / 一般问题 / 优化建议）仅作问题内部归类，不进入交付意见标题。
