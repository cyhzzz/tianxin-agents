# 税务报告生成

把税务分析结论落成一份可交付给管理层、交易对手或存档备查的 Word（.docx）税务报告。

## 一、使用前提

本 skill 只负责**成文交付**。前置分析（资料清点、分税种核查、纳税调整计算、风险分级）由主流程完成，结论以结构化内容（JSON）传入。

**三条红线**：
1. 报告中每个金额都必须能追到用户提供的资料，缺失处标注「资料未提供，未能核实」并汇入待核实事项清单。
2. 法规引用写「法规名称 + 条款要点」，能确认条款号才写条款号，**禁止编造条款号或文号**。
3. 声明页必须写明：本报告基于委托方提供的资料编制，不构成税务机关的执法认定；涉税鉴证类法定报告须由具备资质的机构出具。

## 二、生成路径（按优先级选择）

### 路径 A（首选）：内置 Word 文档能力

用 Skill 工具加载 `tencent-docx`，按第三节的章节结构生成 .docx。适合需要排版美化、图表混排的场景。

### 路径 B（离线兜底）：python-docx 脚本

```bash
# 首次使用安装依赖
pip install python-docx

# 生成报告
python scripts/build_tax_report.py <content.json> <output.docx>
```

脚本特性：封面页（含报告类型与关键口径）+ 中文字体（标题黑体、正文宋体小四）+ 表格边框 + 页脚页码 + 多级标题。

**退出码**：0 成功 / 1 参数或数据错误 / 2 缺少依赖。

**数据问题提示**：JSON 中字段类型错误（该是数组却给字符串、表格缺 headers、单元格为 null 等）不会导致崩溃，脚本会跳过并在 stderr 汇总「数据问题」清单。**看到该提示说明报告内容有缺失，必须修正 JSON 后重新生成，不能直接交付。**

**验证**：生成后确认文件存在且非 0 字节、stderr 无「数据问题」提示。

## 三、内容 JSON 结构

```json
{
  "title": "XX 有限公司年度企业所得税汇算清缴报告",
  "subtitle": "2025 年度 · 查账征收",
  "meta": {
    "报告类型": "年度企业所得税汇算清缴报告",
    "纳税人识别号": "9144XXXXXXXXXXXXXX",
    "纳税人资格": "增值税一般纳税人 / 企业所得税查账征收",
    "所属期间": "2025-01-01 至 2025-12-31",
    "编制人": "银橙AI（注册会计师 · 注册税务师）",
    "编制日期": "2026-03-20",
    "报告编号": "TAX-2026-001",
    "资料范围": "2025 年度财务报表、科目余额表、总账与明细账、各税种申报表、完税凭证",
    "金额单位": "人民币万元"
  },
  "disclaimer": "本报告基于委托方提供的资料编制，未执行涉税鉴证程序，不构成税务机关的执法认定。",
  "sections": [
    {
      "heading": "四、纳税调整项目明细",
      "paragraphs": ["全年共发生纳税调整事项 7 项，合计调增应纳税所得额 186.40 万元，调减 32.50 万元。"],
      "tables": [
        {
          "title": "表 4-1 扣除类调整明细（单位：万元）",
          "headers": ["项目", "账载金额", "税收金额", "调整金额", "依据"],
          "rows": [
            ["业务招待费", "48.00", "28.80", "调增 19.20", "按发生额 60% 与营业收入 5‰ 孰低扣除"],
            ["职工福利费", "96.00", "84.00", "调增 12.00", "超过工资薪金总额 14% 部分不得扣除"]
          ]
        }
      ],
      "bullets": ["需补充：2025 年度研发费用辅助账，用于确认加计扣除基数"]
    }
  ]
}
```

字段说明：
- `title` / `subtitle` / `meta` / `disclaimer` 生成封面页；`meta` 为键值对，顺序即展示顺序。**建议在 meta 中放报告类型、所属期间、纳税人资格、金额单位、资料范围**，让报告第一眼就说明口径与边界。
- `sections[].heading`：章节标题，支持「一、二、」中文序号；`level: 2` 可生成小节标题。
- `sections[].paragraphs`：正文段落数组。
- `sections[].tables`：表格数组，`headers` 表头、`rows` 行数据（二维数组，单元格为字符串）。
- `sections[].bullets`：要点列表，用于风险清单、建议清单。
- 三个内容字段都可缺失，脚本自动跳过。

## 四、三类报告的章节结构

### 1. 税务合规审查报告

| 序号 | 章节 | 必含内容 |
|---|---|---|
| 封面 | 封面与声明 | 报告类型、主体信息、所属期间、资料范围、单位、免责声明 |
| 一 | 审查范围与方法 | 审查的税种、期间、依据的资料、执行的程序、范围限制 |
| 二 | 主体与涉税概况 | 主体身份与纳税人资格、适用税种与税率、税收优惠享受情况 |
| 三 | 分税种审查发现 | 增值税 / 企业所得税 / 个人所得税 / 其他税费 / 发票与征管，逐项列示发现事项 |
| 四 | 风险分级清单 | 分级（高/中/低）+ 事项 + 潜在补税与滞纳金估算 + 依据 |
| 五 | 整改建议与时限 | 按优先级排序，写明整改动作、责任事项与建议完成时间 |
| 六 | 待核实事项（Open Items） | 事项、所需资料、对结论的影响方向 |
| 七 | 附件与资料索引 | 资料清单与计算底稿说明 |

### 2. 税务专业报告

| 序号 | 章节 | 必含内容 |
|---|---|---|
| 封面 | 封面与声明 | 报告类型、委托目的、事项名称、免责声明 |
| 一 | 事项背景与委托目的 | 交易或事项的来龙去脉、要回答的具体问题 |
| 二 | 事实与资料依据 | 已核实的事实、依据的资料清单 |
| 三 | 适用法规 | 法规名称 + 条款要点，注明适用年度 |
| 四 | 分析论证 | 逐层推导，对比不同处理方式的税负与风险 |
| 五 | 专业结论 | 明确的税种、计税依据、税率、申报口径结论 |
| 六 | 执行前提与假设 | 逐条写明结论成立的前提，任一前提变化对结论的影响 |
| 七 | 风险提示与责任限制 | 地方口径差异、政策变动风险、责任范围 |
| 八 | 附件 | 计算过程、法规摘录 |

### 3. 年度企业所得税汇算清缴报告

| 序号 | 章节 | 必含内容 |
|---|---|---|
| 封面 | 封面与声明 | 年度、纳税人识别号、征收方式、适用税率 |
| 一 | 企业基本情况 | 主体信息、经营范围、适用税率与优惠资格 |
| 二 | 会计利润与申报基础 | 利润总额、以前年度亏损弥补、境外所得 |
| 三 | 纳税调整项目明细 | 收入类 / 扣除类 / 资产类 / 优惠类 / 其他，逐项列示账载金额、税收金额、调整金额、依据 |
| 四 | 应纳税所得额与应纳税额计算 | 计算链条：利润总额 → 纳税调整 → 弥补亏损 → 应纳税所得额 → 应纳所得税额 → 减免抵免 → 实际应纳税额 |
| 五 | 已预缴与应补（退）税额 | 分期预缴、汇算应补退金额、申报期限 |
| 六 | 需留存备查资料清单 | 优惠事项、资产损失、关联交易等对应资料 |
| 七 | 待核实事项（Open Items） | 未取得资料与影响方向 |
| 八 | 附件 | 纳税调整计算底稿 |

## 五、写作与数据纪律

1. **口径显式**：金额单位、所属期间、主体身份、纳税人资格在全文统一，并在封面声明。
2. **数字可追溯**：所有金额能追到资料；无出处不出现。
3. **调整必留痕**：纳税调整用「账载金额 / 税收金额 / 调整金额 / 依据」四列呈现，不可只给结果。
4. **法规引用规范**：法规名称 + 条款要点，注明适用年度；不确定条款号不写编号。
5. **风险要落到金额与动作**：每条风险写明「现象 / 依据 / 潜在影响（补税、滞纳金、罚款区间）/ 整改动作」。
6. **不越界**：全文不得出现「税务机关已认可」「无需补税保证」等表述；不得将本报告表述为涉税鉴证报告。
7. **Open Items 收口**：资料不足、口径待确认的事项统一进「待核实事项清单」，不在正文留下无出处的确定性结论。

## 六、交付前自检

- [ ] 封面含报告类型、主体信息、所属期间、金额单位、资料范围、免责声明
- [ ] 已声明收到的资料、缺失的资料，以及口径假设
- [ ] 纳税调整（如涉及）以四列表格逐项列示并附依据
- [ ] 法规引用无编造条款号，均注明适用年度
- [ ] 风险清单已分级，每条含潜在影响与整改动作
- [ ] Open Items 清单已生成
- [ ] 已生成 .docx 文件（非 0 字节），并用 present_files 展示给用户
- [ ] 对话中只给不超过 10 行的要点摘要
