### 为什么没收税率表（`tax-rates.md`，184 行）

先按"硬错误先改对再收"的规矩改了 7 处（记录见下），改完发现**天信自己那份更全**，逐项比对：

| 内容 | 上游 184 行 | 天信 `references/01` 384 行 |
|---|---|---|
| 增值税税率、企税、个税、印花税、房产税、附加税费 | 有 | 有 |
| 2026-01-01《增值税法》施行后的口径变化 | **无** | 有 |
| 加计抵减现存三类（先进制造业 5%、集成电路/工业母机 15%） | **只写"已到期"** | 有，含名单制判定方式 |
| 留抵退税 | **仍是"增量留抵×比例×60%"** | 已指出该公式作废（2022 年后被取代） |
| 工资薪金累计预扣法 + 累计预扣率表 | **无** | 有 |
| 经营所得税率表、个体户 200 万减半 | **无** | 有 |
| 契税、土地增值税、车船税 | **无** | 有 |
| 政策文号总表 | **无** | 有（14 条，带期限） |
| 软件产品即征即退 | 有 | 有（2026-10-31 从这份补入） |

**结论：留着它就是留一个更短、更容易被读到、且含一处作废公式的版本。** 同一件事两个答案，AI 会挑短的那个读。所以只留天信那份，上游这份不入库——原文仍在原包里，需要比对时去 `~/.workbuddy/plugins/marketplaces/experts/plugins/tax-compliance-team/`。

| 4 | 印花税·证券交易 | **0.1%** | **0.05%**，仅出让方缴纳 | 2023-08-28 起减半征收 |
| 5 | 印花税·财产保险合同 | **0.003%** | **0.1%**（保险费的千分之一） | 《印花税法》税目税率表 |

## 读之前必须知道：这份包里有一半是"运行时配置"，不是作业方法

上游是**专家包**形态，原本跑在多智能体运行时里。它的一部分内容在技能里不适用，照做会跑偏：

| 文件 | 里有什么 | 在技能里怎么对待 |
|---|---|---|
| `tax-1-团队总纲.md` | TeamCreate 建团队、按 `Agent ID` spawn 五个子代理、`subagent_type` 参数写法、`SendMessage` 回传、任务下发模板 | **只取六阶段分工与"易混淆场景区分"那张表**。**不要照它建团队、不要 spawn 子代理**——本技能是单文件技能，那五个 Agent ID 在这里不存在，照做会失败或空转 |
| `tax-2` ~ `tax-6` 角色卡 | 每份末尾都有"你是被主理人 spawn 的 teammate，必须通过 SendMessage 回传" | 忽略这段。读的是它们的能力清单与输出模板 |
| 各角色卡的 frontmatter（`name` / `maxTurns`） | 专家包的角色声明 | 忽略。技能不是专家包，这些字段在这里没有作用 |

**真正可用的**：六阶段分工、易混淆场景判定（发票真伪找票务 / 发票背后的合规风险找审计）、各税种计算要点、税费汇总表与合规报告模板、科目表。
