# 天信税务申报

**这不是一个税率查询器。** 税率查错一档，客户多缴几千块；优惠判错一次，三年后补税加滞纳金。县城所的代账客户大多是小微企业，一家一年就几万块钱服务费，经不起一次罚款。

所以第一件事永远是**判清这件事属于哪一类**（§四），不是先翻税率表。

| `上游/` | 两个上游包，**14 个文件**原样收录、一字未改：`tax-compliance-team`（专家团 9 个，分工与科目表）、`tax-advisor-expert`（银橙税务师 5 个，财税一体 + Word 报告成文） | 上游，只读 |

## 三、上游有什么、没有什么

**有**（能直接用的）：六阶段分工与角色边界、各税种计算要点、税费汇总表与合规报告模板、会计科目表、发票处理流程；银橙补充的**财税一体分析、四类响应模式、分税种核查清单、Word 报告成文脚本**。

**没有**（写了才算有的）：表间勾稽的逐项校验、风险指标的算法与阈值、异常发票的处置路径、申报前自查清单、政策文号与期限。这五块正是 `references/01~05` 存在的原因。

**半份是运行时配置**：`tax-1` 讲的是 TeamCreate、`subagent_type`、`SendMessage`，`tax-2~6` 末尾都写着"回传主理人"。这些在技能里没有对应机制，忽略即可。

## 四、判类：六类事项，走不同的路

| 客户说的 | 实际是什么 | 走哪条 |
|---|---|---|
| "这个季度要交多少税" | 多税种计算 | §五 算税链 → `references/02` |
| "帮我报一下" | 申报表填报与勾稽 | §五 第⑥步 → `references/03` |
| "去年汇算清缴怎么做" | 企业所得税年度汇缴 + 纳税调整 | `references/02` §三 |
| "我们能不能享受小微优惠" | 优惠**资格判定**，不是算税 | §六 → `references/01` |
| "税务局来查了 / 我自己想查查" | 风险扫描 | `references/04` |
| "这张发票能不能用" | 发票合规审查 | `references/05` |

**最常见的错**是把第五、六类当成第一类。客户说"帮我看看要交多少税"，实际他手上有一批来路不明的发票——这时候先算税是错的，得先把发票过一遍，否则算出来的数是虚的。

## 五、算税链：顺序不能换

```
① 定身份     一般纳税人 / 小规模；查账征收 / 核定征收；行业；注册地
     ↓       身份决定税率档次、决定能不能用简易计税、决定地方附加税率
② 定期间     月 / 季 / 年；本期的起止日
     ↓       期间错一天，跨期收入的归属就错
③ 取计税依据  从账上取，不从客户口述里取
     ↓       销项、进项、利润总额、工资总额、合同金额
④ 匹配优惠   逐项判定资格，不是"大概符合"
     ↓       见 §六，这里最容易出错
⑤ 算应纳税额  按 references/02 的公式，逐税种算
     ↓
⑥ 勾稽复核   申报表之间、表与账之间对不对得上
     ↓       逐项清单见 references/03
⑦ 出汇总表   见 §七
```

**第 ③ 步是分水岭。** 计税依据必须能从账上指出来——哪张凭证、哪个科目、哪个月。客户说"大概卖了八十来万"，这个数不能用来报税。县城所客户很多连账都不全，这时候要么先补账，要么在交付物上写明"依据客户提供数据，未经账面核对"。

## 六、优惠匹配：三条硬规矩

**规矩一：先判资格，再算金额。**
优惠不是"看起来符合就能用"。小型微利企业要同时满足"335"三个数加一个行业条件；高新技术企业要有证书且在有效期内；研发加计要能按项目归集辅助账。资格不成立，算出来的减免额一分都不能用。

**规矩二：政策有期限，逐条标出来。**
现行主要优惠大多执行至 **2027 年 12 月 31 日**，但这不是"永久有效"，是"这一轮到期时间"。`references/01` 每一条都标了文号和期限，**报税前必须核一遍是否延续**。

> ⚠ 最容易踩的一个坑：生产性服务业加计 5%、生活性服务业加计 10%，**2023-12-31 已到期、未再延续**。2024 年起仍按此申报的，要更正补税 + 按日万分之五滞纳金；被认定偷税处 0.5–5 倍罚款。现行有效的加计抵减只剩三类（先进制造业 5%、集成电路 15%、工业母机 15%），且都是名单制或需行业判定。**代账客户里凡属现代服务、生活服务业的，核一遍 2024 年以来的附表四。**

**规矩三：叠加与择优要分清。**
- **可以叠加**：六税两费减半可与其他优惠叠加（财政部 税务总局公告 2023 年第 12 号第四条）。
- **不能叠加，只能择优**：增值税加计抵减多项并存时，同一期间只能选一项。
- **自动适用**：小微所得税、小规模减免，填表即享、无需备案，但要留存备查资料。

## 七、交付物

### 主交付物：税费计算汇总表

模板直接抄 `上游/tax-2-申报专员.md` 的「输出规范」一节（税种 / 计税依据 / 税率 / 应纳税额 / 减免 / 实缴）。

**天信加的一条硬要求——表末必须有「数据来源与限制」**：

```
数据来源与限制：
- 计税依据取自 {账套/报表/客户提供清单}，{已/未}经账面核对
- {如未核对，写明后果与建议}
```

**这一节不能省。** 它是这份表能不能作为执业记录的分界线——同样是"算了一下"，写了来源限制的是专业意见，没写的是随口报价。

### 其他交付物

| 场景 | 交付物 | 要点 |
|---|---|---|
| 申报 | 申报前自查清单 | 逐项打勾，未通过的写明原因（`references/03`） |
| 汇缴 | 纳税调整明细表 + 汇缴申报表要点 | 不编行次编号，以 A100000 及明细表为准 |
| 优惠适用 | 优惠资格判定备忘 | 逐条列出条件、证据、结论 |
| 风险自查 | 风险指标表 + 处置建议 | 见 `references/04` |
| 发票审查 | 异常发票清单 + 处理意见 | 见 `references/05` |

## 八、要出报告时：调用「天信文档与报告」技能

作业做完要交付的东西（税费汇总表、汇缴备忘、风险自查报告、给客户的说明函），**排版不要自己拼**：

- 出 Word / A4 PDF / 网页长页 / 演示 deck → 调用 **`天信文档与报告`** 技能。它带天信品牌规范（0 圆角、navy `#00338D` + 亮蓝 `#0F62FE` + 金 `#B8860B`、Noto SC）、四轨出版流程、页眉页脚与目录规则。
- **分工**：本技能负责内容对（数从哪来、怎么算的、依据哪个文号），格式与品牌交给它。
- 若目标环境没装那个技能：直接输出 Markdown 或简洁表格，并说明"排版需另装天信文档与报告技能"。**不要自创品牌样式**——自己拼一个像天信的版式，比给纯文本更糟。

## 九、边界与红线

**能力边界**：分清"判性质"和"做作业"。定性拿不准时，写"待核实 + 需客户提供什么"，不要用算得很快但定性错的数字交差。本技能自带判类、算税、勾稽、风险、发票五块方法，装到任何机器上都能独立跑，**不指向别的技能文件**。

**红线**：

- **不替代 CPA 判断。** 跨境涉税、企业重组、重大税务争议、涉税刑事风险、出口退（免）税 → 直接转持证 CPA / 税务师事务所，不在所内自行处理。
- **不编政策。** 拿不准的政策，写"待核实，以主管税务机关口径为准"，不写一个看起来合理的数字。税率与优惠比例必须能追到文号与执行期限。
- **不承诺结果。** 不做"这样报一定没问题""这个方案能省多少税"的承诺。给的是合规路径与依据，结果是税务机关认定的。
- **数据来源必须可追溯。** 计税依据要能指回账、凭证、报表。客户口述的数字标明来源与未经核对的限制。
- **政策时效以查询日为准。** `references/01` 核实于 2026-10，主要优惠执行至 2027-12-31。跨年使用前重核。
- **客户信息不外传。** 涉税数据属商业秘密，不进示例、不进公共仓库。
- **上游只读。** 改一个字或往里加文件，仓库自检第 10 项就报错（校验和对不上）。要补要改，改本文件或 `references/`。

## 反馈与改进

这份技能是 [cyhzzz/tianxin-agents](https://github.com/cyhzzz/tianxin-agents) 的**副本**。
**你在这里的修改不会自动回到仓库**——会话一结束就没了。

遇到下面任一情况，请留下改进提案，不要只在会话里绕过：

- 内容有误、政策已变、数字对不上
- 缺了某一类常见情形，你只能临场发挥
- 用户纠正了你，而纠正的内容本该写在这份文件里

### 优先：能改就直接改文件，再回传

AI 遇到技能有问题，默认做法是临场绕过——这次能用，下次还是错的。
**更好的做法是直接改 `~/.workbuddy/skills/天信税务申报/` 下的文件**（改本文件或 `references/`，别动 `上游/`），然后告诉用户：

> 我改了「天信税务申报」里的 `references/01-税率与优惠速查`，改动还没回仓库。
> 克隆 https://github.com/cyhzzz/tianxin-agents 后跑这一条就能提 PR：
> `python contribute.py --from-installed ~/.workbuddy/skills/天信税务申报`

这条路径最有用——它产生的是**可以逐行 review 的真实改动**，不是一段描述。
