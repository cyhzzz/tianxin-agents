## 为什么上游税率表没有入库

上游 `tax-rates.md`（184 行）先按"硬错误先改对再收"改了 7 处，改完发现天信 `01` 更全，逐项比对后不收录：

- 缺 2026-01-01《增值税法》施行后的口径变化
- 加计抵减只写"已到期"，没有现存三类（先进制造业 5%、集成电路/工业母机 15%）
- 留抵退税**仍写已作废的"增量留抵 × 进项构成比例 × 60%"**
- 无工资薪金累计预扣法、无经营所得税率表、无契税/土增/车船、无政策文号总表

同一件事两个答案，AI 会挑短的那个读。所以只留 `01`，上游原文仍在原包里可比对，7 处修正记录留在 `上游/README.md`「修正留痕」。

**反过来也做过一次**：删之前逐项比对，才发现天信 `01` 漏了上游唯一有的**软件产品增值税即征即退**，已补入 `01` §1.6。不比对就删，等于一边删重复一边丢东西。

## 6 处硬错误与 1 处补漏（都记在 `上游/README.md`）

原专家税率表是 2023 年口径，直接搬会让客户少缴、补税加滞纳金：

| 原内容 | 问题 | 处置 |
|---|---|---|
| 生产性服务业加计 5% / 生活性服务业加计 10% | **2023-12-31 到期未延续**，2024 年起继续申报要补税 + 滞纳金 + 可能罚 0.5–5 倍 | 标为已到期，单列警示；现行只剩三类 |
| 留抵退税"增量留抵 × 进项构成比例 × 60%" | 2019 年部分退还口径，已被取代 | 改为《增值税法》法定化表述，明确"不要再用 60% 公式" |
| 小规模征收率含 5% | 《增值税法》2026-01-01 施行后统一 3% | 标注新法口径 + 申报栏次调整 |
| 财产保险合同印花税 0.003% | 旧《暂行条例》按投保金额贴花 | 改为印花税法：**保险费的千分之一** |
| 证券交易印花税 0.1% | 漏了 2023-08-28 起减半 | 补：实际 **0.5‰**，只对出让方征 |
| 各项优惠只写"以最新政策为准" | 无文号无期限，无法判断是否还有效 | 逐条补文号与期限，区分制度性与阶段性 |
| （补漏）软件产品即征即退 | 上游有、天信 `01` 原缺 | 补入 `01` §1.6，含三项享受前提 |

## 能力边界：判在定性，做在这里

| | 判断（定性） | 作业（算与报） |
|---|---|---|
| 管什么 | 业务怎么定性、红线在哪 | 怎么算、怎么填、风险在哪 |
| 典型问法 | "这笔收入算不算价外费用" | "这个季度增值税怎么算、表怎么填" |

**本线技能独立运行**：判类、算税、勾稽、风险、发票五块方法都在技能内，不指向其他技能文件。
若所内另装「天信实务知识库」，其 `cards/tax-practice.md` 可作深读补充；两处数值不一致时，**以 `references/01` 为准**（带文号与核实日期）。

## 上游原文（`上游/`）

平台 `tax-compliance-team` 的 1 个组长 + 5 个专员 + 税引擎，**9 个文件 / 1252 行原样收录、一字未改**（税率表按上文理由未收）。

**读之前必须知道**：这个包原本跑在多智能体运行时里，`tax-1` 讲的是 TeamCreate / spawn / SendMessage，`tax-2~6` 末尾都写着"回传主理人"。这些在技能里没有对应机制——**取它的分工与表格，不要照它建团队**。

**注意**：该上游包未附许可证文件（`plugin.json` 的 license 为空），法律上属"保留所有权利"，
**仅限所内使用，不得随仓库对外分发**。这与代账线的 `finance` 包（Apache-2.0）不同。
